## 0. 使用前提

- 已保存三台服务器与账号：Emby「果服」/ `donxuelian`、Jellyfin 10.10.7 / `tafei`（管理员）、飞牛影视 0.9.8 的已保存账号。地址、密码、令牌不得写入结果文件、命令行或截图。

- 所有“通过”必须同时满足：观察方法执行过、判据全部成立、证据落盘。只看到界面、只读代码、只跑离线探针都不算通过。

## 4. 本轮明确不做的写入项

以下操作**一律不执行**，也不要用“只点一下看看”绕过：

- 收藏/取消收藏、标为已看/未看、从继续观看移除、下载。
- 刷新/编辑/识别/重置元数据、修改封面、删除媒体/剧集/版本。
- 修改密码、创建/删除账号、退出登录以外的账号管理写入。
- 创建/删除/编辑媒体库、提交媒体库排序、修改服务器设置、开关任务计划。
- Jellyfin 管理页的任何保存按钮；飞牛「更多」菜单里的刷新元数据、手动匹配、解除匹配、编辑元数据、删除。
- 创建 API 密钥、修改服务器网络/转码/日志设置。
- Plex 不在本轮范围。

允许的写只有：真实播放产生的观看进度/续播点（验证目标），以及本地应用设置（聚合开关、窗口尺寸）。本地设置改动要记下来并恢复。

## 5. 不可验证边界与已知证据缺口

1. **Jellyfin 媒体库界面此前只在假传输/假数据上验证**：分类、排序、筛选、布局、建议货架的选项结果与视觉密度没有在真实库核对过（`docs/Jellyfin支持.md:46`）。J3/J4/J6 是本轮必须重点补的缺口。
2. **Jellyfin 真实播放没有既有实服证据**：文档明确“真实 Jellyfin 写入与真实播放按授权档另行验证”；10.10.7 上只只读核对过公开信息、管理页路由、同文档切页与皮肤（`docs/Jellyfin支持.md:46`）。J7–J10 是本轮首验。
3. **飞牛真实播放未验证**：0.9.8 / 0.8.43 上只只读核对过七项页面、筛选、布局与排序界面；“真实播放和真实写入仍未验证”（`docs/飞牛影视.md:27`）；更早一轮的真实飞牛服务器是空库（`PROGRESS.md:885`）。若本轮库仍为空，N2/N4/N5/N6 记 `BLOCKED`，不要用离线测试补。
4. **跨服务器版本、聚合主页、账号菜单、左栏分组此前是假传输/探针覆盖**：`--probe-shell` 的聚合检查使用假服务器，“探针是否实际通过以本轮运行报告为准”，不能替代真实服务器（`docs/开发与验证.md:5`；`docs/多服务器与多账号.md:36-40`）。
5. **非管理员账号是否存在未知**：J11/N7/A4 的“非管理员隐藏”只有在存在普通 Jellyfin/飞牛账号时才能实服验证；否则只能引用代码与离线探针，记为证据缺口。
6. **飞牛 `Range 206` 没有安全的取证通道**：Momoka 不手工发 Range，Range 由 mpv/FFmpeg 发出；当前工具链没有“不把 Authorization 落盘”的抓包或服务端日志通道。可接受的替代只有：运维提供只读访问日志（不导出 Authorization），或同账号官方网页 DevTools 观察同一端点的 206（属于端点能力，不等于 Momoka 请求的 206）。两者都拿不到时，N5 只能记“URL 与文件信息一致”，**不能声称 206 已验证**。
7. **内置后端日志是 URL 证据的前提**：`LibMpvBackend` 才打印媒体 URL；外部 mpv 后端只记“通过验证身份的管道传递播放请求”，不打印 URL（`src/Momoka.Core/Playback/MpvProcessBackend.cs:46`）。若当前配置是外部 mpv，J7/N3 不能用日志取证；不要为了取证改用户后端设置，记缺口或改用服务端访问日志。
8. **“三源同时在线”依赖环境**：必须有 Emby、Jellyfin、飞牛三台已保存且能登录的来源。少一台时 A1/A2/A5/A6 记 `BLOCKED`，不能把两源结果当三源通过。
9. **跨服务器版本依赖真实同片**：A5/A6 需要至少一部在两台服务器上都存在、且有相同可信刮削标识的媒体。没有这样的条目时，A5 只能验证“不误合并”，不能验证“出现另一台版本”；A6 记 `BLOCKED`。
10. **本轮不是完整回归**：不跑四道闸门、不跑全量探针、不声称“全部测试绿”。本轮结论只覆盖本清单的实服功能与真实播放。
11. **服务器写入不在本轮**：飞牛“更多”写入、Jellyfin 管理写入都没有执行过（`docs/飞牛影视.md:12`；`docs/Jellyfin支持.md:46`），本轮也不执行。
12. **证据不得含凭据**：截图/日志/命令行不得出现令牌、密码、`Protected*` 字段或带 `api_key` 的 URL。日志 URL 已去查询串，但仍要人工扫一眼；Jellyfin 控制台截图不要拍到 API 密钥页。

## 6. 建议执行顺序与停止条件

1. 先做 **J1 → J2**（连接/恢复/权限），再做 **J3 → J4 → J5 → J6**（浏览/搜索/详情），最后做 **J7 → J8 → J9 → J10**（原画/无转码/画面/进度）。J11 放在播放后做，避免控制台占用窗口。
2. 飞牛：**N1 → N2 → N3 → N4 → N6 → N5 → N7 → N8**。N5 的 206 证据先确认有没有安全通道；没有就按缺口记录，不阻塞 N4/N6。
3. 聚合：**A1 → A2 → A3 → A4 → A5 → A6 → A7 → A8 → A9 → A10**。A5/A6 需要先在两台网页确认同片标识，避免把“没找到同片”误判成“功能失败”。
4. 任一 **P0 失败**：保留截图/日志，记录确切现象与服务器端读数；不要用重试到绿、改设置、改库来掩盖。继续执行不受影响的 P1/P2，但最终结论必须写失败项。
5. 任一 **P0 `BLOCKED`**：写清缺什么（库空、账号缺、同片缺、无 206 通道），不要把 P1/P2 的通过拼成“P0 通过”。
6. 收尾：恢复 `AggregateMode=false`、当前来源 Emby「果服」/`donxuelian`（A9），关闭应用，保存本轮证据目录清单。

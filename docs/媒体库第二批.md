# 媒体库第二批：把媒体找得到

本批沿用电影电视剧媒体库、详情和搜索页面，按各后端的协议分别实现。真实 Plex PMS 尚未配置，本文件的 Plex 结论只包含官方静态源码与离线协议证据。

另外两部分分别见 [Plex 筛选排序与字母跳转](媒体库第二批-Plex浏览.md)和 [Emby/Jellyfin 搜索扩展](媒体库第二批-搜索.md)。整合时显式拒绝同时携带人物关系和普通库筛选的查询，避免普通筛选构造覆盖原关系字段。

## Plex 人物与题材

详情读取 `Role`、`Director`、`Writer`，保留名字、角色和头像。演员、导演、编剧的服务器标签 ID 与来源库、媒体类型一起形成运行期身份；同名不同人、相同 ID 的不同库或署名类型不会被合成同一人物。缺标签 ID 或来源库时仍显示可读署名，人物卡不提供导航按钮。

有身份的人物进入当前来源库中的作品页。电影库查询电影，电视剧库查询节目；季或单集中的人物关联也按所属电视剧库显示节目。题材同样只在该库中关联：服务器给出标签 ID 才生成链接，其他题材保留文字。页面标题明确显示来源库编号，返回栈和来源账号沿用现有浏览页面。没有启用 Plex 云人物目录，也没有跨库人物或题材聚合。

`PlexBrowseRelation` 保存 `SectionId`、数值媒体类型 1/2、`actor/director/writer/genre` 字段及原生正十进制 ID。作品请求为 `GET /library/sections/{section}/all?type={type}&{field}={id}`，页起点和大小仍使用 `X-Plex-Container-Start/Size` 请求头；关系页的条件不会因工具栏刷新丢失。非法关系、跨库组合或关系改用其他后端在 HTTP 前拒绝。头像沿用现有图片传输的同源边界，不给外部头像地址附加令牌。

来源是官方 Plex Web **4.163.0 / 8246fd2** 的实际发布产物：`main-8792-0fadf59092c873ab638b-plex-4.163.0-8246fd2.js`，SHA256 `bdb3e4ce5d49b5eb6be48e11a4aea0f33a357561f8bf1e1303d31255f701cd97`。该版本是固定实现依据，不宣称最新版。

- 模块 84160 的 `sz/oz`（原文件字符位置 1372533 附近、`oz` 起点 1372706）按 `metadata.librarySectionID` 找来源目录，使用原生 `filter` 或 `director/writer` 标签 ID；题材调用在 1390862 附近使用 `genre`。
- 模块 7537（紧随人物导航模块 3632）构造来源目录 `/all` 和 `actor=id`；模块 29264 将同一人物多种署名的原生 filter 合成条件。Momoka 首轮按各署名类型独立浏览，不加入复杂 OR 编辑器。
- 模块 3632（2122746）及 `/library/people` 路径（2123110）通过模块 20761 的常量 `myPlex`（449947）选择云元数据来源；该路径没有被当成本地 PMS 路由。
- 官方模块 56642 按名字合并演员/工作人员卡。Momoka 按库、类型和 ID 区分署名，避免同名人混合；这是本地明确选择。

`PlexMediaTests.People` 覆盖单对象/数组、数字/字符串 ID、重复与同名、缺身份静态展示、头像偏好、四类关联请求及非法关系零 HTTP。`Momoka.PlexAffordanceTests` 使用当前 Shell DLL，执行真实详情 VM、人物卡和提取的题材绘制/事件处理，核对逐项链接、来源切换及取消后的旧事件拒绝。它不创建窗口，不代表 WinUI 实屏、焦点或真实 PMS 结果；窗口验证及最终主树交付由批次收尾执行。

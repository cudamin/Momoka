# Plex

在 Momoka 的服务器连接页填写 Plex 服务器地址（例如 `192.168.1.5`、`192.168.1.5:32400` 或从浏览器复制的带 `/web` 的地址），应用自动识别服务类型。登录使用 **Plex 账号**（plex.tv）而不是服务器本地账号：Plex 服务器本身不校验账号密码，账号由 Plex 的账号服务认证，拿到的令牌再交回目标服务器核对这台服务器有没有共享给该账号。保存的密码与令牌走现有的 DPAPI 凭据保险箱，与 Emby、飞牛共用同一套。

连接后复用 Momoka 的主页、媒体库、搜索、电影与剧集详情和播放界面。库首页读取服务器提供的媒体类型、筛选与排序目录，支持题材、年份、已看状态、分辨率等已声明的条件组合，以及标题排序下的字母跳转；缺目录时收起对应入口。具体范围见本节与 [Plex 技能](../.claude/skills/momoka-plex-api/SKILL.md)。播放器使用服务器给出的原始文件地址（`Part.key`），令牌只在请求头 `X-Plex-Token` 里，不进地址、不进日志、不进启动参数；支持续播、内嵌音轨、单文件版本的 Plex 外挂字幕以及进度上报（`/:/timeline`）。「标记为已观看 / 未观看」走 `/:/scrobble` 与 `/:/unscrobble`。

一个 `Media` 对应一个版本，其多个 `Part` 顺序拼成整片时间轴，续播、拖动与播放完成都按整片计算。多段版本必须提供可累计的有效 Part 时长，并保持各段内置轨道布局一致；不满足时略过该版本，保留其它可用版本。分段外挂字幕尚无整片时间轴，相关轨道不显示，内置字幕和关闭字幕仍可用；旧外挂字幕选择会明确拒绝，避免误选另一条字幕。每段地址仍分别通过播放地址与传输安全边界。

上报的 `key` 使用条目 `/library/metadata/{ratingKey}`，`time` 与 `duration` 使用整片毫秒。固定官方 `plexinc/plex-for-kodi` 提交 `97191f248a20223bb93296789c010ff2204a9c76` 的 `nowplayingmanager.py:171-187` 使用 `timeline.item.key`；`lib/player.py:174-186` 把当前 Part 偏移加到当前播放秒数。此源码纠正旧说明的 part key，不代表真实服务器落库已验证。

已看写请求成功后立即保留确认位，统计由独立 metadata 补读取得；补读失败会提示“状态已保存，但刷新失败”，不会因此重复发送写入。补读401的同身份重新认证只重读，写请求本身401仍沿现有认证重试。这里的成功是原HTTP任务完成，不是仅收到响应头。上述行为由匿名协议、实际卡片及详情VM回归覆盖，真实 Plex 服务仍未验证。

## 与其它后端不同的地方

- 首页已接入 Plex 原生库推送；2026-11-10 对照官方首页去掉无条件 30 秒 HTTP 轮询。扫描中 10 秒轮询属于官方推荐货架页，Momoka 当前无此 Plex 页面。连接、筛选事件、一手来源与验证边界见 [媒体库实时更新](媒体库实时更新.md)。

- **地址默认端口是 32400**，但只对 `http` 生效；`https` 且没写端口的地址保留 443，因为那种写法基本是反向代理，硬指到 32400 会把能用的配置改坏。浏览器地址栏里的 `/web` 或 `/web/index.html` 会被剥掉。
- 用户明确写出的 HTTP `:80` 会保留，包括保存后的显示地址再归一化；IPv6 主机只保留一层方括号，无端口 HTTP IPv6 同样使用 32400。端口是否明确填写按原始地址的 authority 判断，不拿 `Uri.IsDefaultPort` 代替这一事实。直接 Plex 与共享显示入口都有离线表驱动往返回归，不需要连接服务器。
- **没有用户列表。** Plex 服务器不提供 Emby 那种公开用户列表，登录页因此只有用户名与密码两格，直接手填。
- 普通视频播放列表与电影／电视剧合集新增独立目录及成员协议。播放列表创建／添加／成员移除／排序按原生 playlistItemID；合集创建／添加／成员移除按单媒体库权限，均不删除磁盘文件。编辑入口按当前 provider 和清单显式权限显示；智能、只读、未知账户要求不开放写。具体来源、先选初始媒体创建、回执与验证边界见本节与 [Plex 技能](../.claude/skills/momoka-plex-api/SKILL.md)。
- **未接入的入口收起**：收藏、下载到设备、修改元数据、识别、删除媒体、章节缩略图、遗漏集、搜索字幕、通知和网页控制台。它们包含协议语义差异和客户端尚未实现的能力，不能统一解释为 Plex 服务端没有接口。
- 收藏快捷按钮和宽／窄详情按钮也按条目所属来源单独收起；已看按钮保留。旧收藏命令直接调用不会发请求、修改本地状态或报误导失败，聚合列表中的 Emby／Jellyfin 收藏不受 Plex 默认来源影响。
- 演员、导演、编剧与题材可按服务器标签 ID 在当前来源库内关联浏览；缺 ID 时保留文字或静态人物卡。来源切换、返回与重入重新判断，旧点击不借当前其他账号执行。没有跨库或云人物聚合，具体字段、固定官方源码与验证边界见本节与 [Plex 技能](../.claude/skills/momoka-plex-api/SKILL.md)。Emby／Jellyfin 使用各自题材语义。
- **管理入口一个都没有。** Plex 没有本客户端已接入的管理接口，所以「设置」左栏在 Plex 名下不会多出管理目录。飞牛影视另有独立的帐号及管理员影视服务器目录，不能据此类比。

## 协议依据与验证边界

协议面见 [Plex 协议技能](../.claude/skills/momoka-plex-api/SKILL.md)，接口清单见其 [接口表](../.claude/skills/momoka-plex-api/references/endpoints.md)。

**这一版没有对任何真实 Plex 服务器做过核对。** 所有路径、字段名与参数都是从 Plex 的公开接口约定写下来的，只用离线假传输验证了「本客户端发出什么、怎么读回答」：

- `PlexProtocolTests`：地址归一化（默认端口、https、`/web`、账户信息、非法 scheme）、条目标识与媒体地址不能逃逸服务器、`/:/` 特殊端点的拼法、令牌只在请求头、`/identity` 不带令牌、401 判为令牌失效且不回显服务端正文、跨来源重定向不发第二次请求、账号密码走正文且客户端标识走头部、分页走 `X-Plex-Container-*` 头、排序与类型走查询串、scrobble 与 timeline 的参数与毫秒单位。
- 其注册的 `PlexContainerTests` / `plex-container-fixture` 覆盖普通清单独立目录、真实成员身份、分页、显式能力和写前权限重新核对、同库同类合集、只读与智能拒绝、同服 URI、重复成员、移除／排序、确认成功后正文失败／取消、确定拒绝、未知回执及跨源写重定向；没有真实 PMS 写入或实际清单页面证据。
- `PlexMediaTests`：登录、令牌失效后同身份恢复、已保存账号恢复（不重登账号）、音乐库被挡在外面、搜索分类、详情把 `Media`/`Part`/`Stream` 映射成媒体源与音轨、季集与「接下来播放」、播放规划（原始地址、请求头、metadata key）、进度上报、菜单裁剪，以及不支持的收藏操作不向服务器发任何请求。其注册的 `PlexMultipartTests` 覆盖版本与分段区分、75 分钟续播、非法时长、全段地址边界与轨道限制。
- `plex-multipart-native-fixture` 使用本树批准 SHA256 的 libmpv，生成本地 PCM 文件、null 音视频输出、禁用户配置/脚本/自动外挂加载。EDL 自身需要允许引用；探针引用仅由自身生成的 PCM，不接收媒体路径或 URL。它核对整片时长、跨段起播/seek 和只有最终 EOF，不能替代真实服务器、独占窗口、外部 mpv 或真实字幕验收。
- `plex-multipart-http-native-fixture <本地绝对libmpv-2.dll路径>` 将自生成 PCM 通过随机 loopback 端口、真实受管认证转发与 EDL 交给同一批准内核，另核每段映射、Range 和原生全局认证头为空；不访问真实服务器。
- 媒体库 ID 使用 `Directory.key`，电影／剧集条目继续使用 `ratingKey`；库 key 缺失、null 或空白时拒绝本次库响应，不生成可点击的空 ID 入口。新增库映射回归直接使用 `GetViews` 产物验证两库浏览、逐库最近添加、随机轮播及跨来源导航键，不执行登录或真实服务器请求。
- 指定剧的“下一集”沿既有 On Deck 原始分页继续读取，直到找到足量目标或读完，保留服务器顺序；不会因目标在全服第 21 条或更后面就返回空。后页失败或取消会传播，目标靠后时请求数会增加。匿名回归覆盖分页头、限量、缺总数、短页和续播替换规则，不证明实际 PMS 排序或 WinUI 卡片更新。
- 媒体总码率与轨道码率从 Plex 的 kbps 转为共享 bit/s；转换后超过共享整数范围时保持未知，媒体信息使用原有单位格式化。剧／季用有效的 `leafCount`、`viewedLeafCount` 判定全部看完并提供未看集数；空、缺失或矛盾统计不判已看完，电影／单集继续用 `viewCount`。这两项已对照固定官方 Web 4.163.0 / 8246fd2 源码，并通过实际映射、媒体信息、菜单和匿名 HTTP 回读测试；不是实际 WinUI 或真实 PMS 验证。

- `Momoka.PlexAffordanceTests`：实际卡片命令、当前 Shell 详情 VM、题材重画与旧事件守卫；假传输核零无效收藏写请求并保留已看、聚合混来源和旧命令执行边界。源模板／OneWay 通知契约不是实际 WinUI 布局、焦点或 UIA 证据。

**没有验证的是**：真实 Plex 服务器是否按上面这些路径与字段回答；真实播放、进度上报落库、多账号切换、反向代理与 HTTPS 下的实际行为；plex.tv 账号服务的实际响应形状与错误码。第一次连真实服务器时请按只读顺序来（先只填地址点「连接」，确认识别出 Plex 与服务器名，再登录），并把观察结果补进这一节。

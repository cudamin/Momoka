## 1. 产品与技术栈

Momoka 是第三方媒体库桌面客户端：用户自己搭 Emby、Jellyfin、飞牛影视或 Plex 服务器，本程序负责浏览、播放和管理。

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 语言与运行时 | C# / .NET 10 | `global.json`、各 `csproj` |
| UI 框架 | WinUI 3（Windows App SDK） | `src/Momoka.Shell/Momoka.Shell.csproj` |
| 部署形态 | 非打包（`WindowsPackageType=None`）、仅 x64、框架依赖 | 同上 |
| 播放内核 | libmpv（随包 `libmpv-2.dll`，不入库） | `src/Momoka.Core/Playback`、`src/Momoka.Core/Mpv` |
| 分发 | GitHub Releases 安装包；Microsoft Store 商店包 | `tools/publish.ps1`、`tools/installer.ps1` |
| 许可 | 本程序 MIT；随包 libmpv 为 LGPL 构建 | [LICENSE](../LICENSE)、[THIRD-PARTY-NOTICES](../THIRD-PARTY-NOTICES.md) |

服务端支持分四套，各自的实现与验证边界不同：

| 服务 | 协议层 | 实测边界 |
| --- | --- | --- |
| Emby | `Core/Emby`（基址恒以 `/emby/` 结尾，`X-Emby-Authorization` + `X-Emby-Token`） | 4.10.x 已实测登录恢复、库读取、原画播放、续播与部分管理写入 |
| Jellyfin | 同一套 `Core/Emby`，基址不带 `/emby/`，`Authorization: MediaBrowser` | 10.10.7 已实测保存登录恢复、库读取、原画播放与续播；管理写入未验证；12.x 只做了协议对照 |
| 飞牛影视 | `Core/FnNas`（`trim.media` / `trimemedia`，独立签名） | 网页 0.9.8 / 服务 0.8.43 已实测登录恢复、库读取、原画播放、续播；管理写入未验证 |
| Plex | `Core/Plex`（plex.tv 账号登录 + 服务器直连） | **只做了协议与离线测试**，没有对真实服务器核对过，见 [Plex 支持](Plex支持.md) |

音乐库统一使用同一套界面与底部播放栏，服务端接口按各家实际能力适配（Emby/Jellyfin 走 Items 查询，飞牛走独立音乐协议，见 [音乐媒体库](音乐媒体库.md)、[飞牛音乐协议](飞牛音乐协议.md)）。

## 2. 仓库结构

```
src/Momoka.Core      与 UI 框架无关的领域层：协议、设置、播放决策、纯规则
src/Momoka.Shell     唯一的桌面应用：WinUI 外壳、页面、视图模型、探针、自检
tests/               一个主测试宿主 + 数十个专项测试工程（见第 11 节）
tools/               构建、发布、质量、验证与回归入口脚本
assets/              随包资源：mpv 运行时载荷、mpv-ui（uosc 与 Lua 脚本）、着色器
docs/                功能文档、命令手册、交付台账与本文
.claude/skills/      按任务读取的项目技能（协议、播放、界面、验证等）
```

### 2.1 分层

- **`Momoka.Core` 不引用任何 UI 框架，也不带 NuGet 包引用。** 这是硬约束：主测试宿主是一个普通控制台程序，靠这条才能直接加载 Core。HTTP、持久化、播放决策、字幕/轨道规则、主题色推导都在这里。
- **`Momoka.Shell` 是唯一 `WinExe`。** 它持有 WinUI 视觉树、依赖注入容器、窗口与原生互操作，也放得下纯 UI 行为（code-behind）。
- **方向是 `View → ViewModel → Service → 外部世界`**，但不要求每个文件都走完整链路：纯展示判断就近留在页面，可复用的业务规则做成 Core 里的纯函数并配测试。

### 2.2 两个容易记错的位置

- `ActivationListener` 在 `src/Momoka.Shell/ActivationListener.cs`（无 UI 依赖，被主测试编译链接），不是历史路径 `Shell/ActivationListener.cs`。
- 依赖注册只有一处：`src/Momoka.Shell/Composition/ShellServices.cs`。找「谁创建了谁」先看它。

## 3. 启动与进程模型

入口是 `src/Momoka.Shell/Program.cs`，`Main` 手写（`DISABLE_XAML_GENERATED_MAIN`）：进程要在任何 XAML 出现之前完成数据目录迁移、单实例判定和日志初始化。

### 3.1 启动顺序

1. **解析命令行**（`src/Momoka.Core/Infrastructure/StartupArgs.cs` 的 `Has` / `Text` / `Number`）。
2. **自检隔离**：`--self-check` 先建独立运行目录（`SelfCheckRun.Create`），从「真有 `settings.json` 的那份配置目录」复制一份设置，不迁移、不写生产目录。
3. **探针分支**：`--probe-shell`、`--probe-subtitles`、`--probe-composition`、`--probe-cursor`、`--probe-player-motion` 各自把数据目录换成本次运行的子目录，然后照常起窗口跑用例。
4. **数据目录迁移**：`SettingsStore.PrepareStartupData(AppPaths.PriorRoots)` 从旧产品名目录搬设置与缓存；失败不阻止启动。
5. **旧实例检测**：旧名字版本还开着时，向它的激活事件发一次信号后退出。
6. **单实例互斥**：命名 `Mutex`；第二个进程只发激活事件，不建窗口。
7. **`Run`**：起日志 → 注册异常处理 → `Application.Start` → `App.OnLaunched`。

`App.OnLaunched` 里依次是：探针分支 → `ShellServices.Build(paths, selfCheck)` → 读主题并 `ThemeHost.Apply` → 建 `ShellPage` → 套进 `HostWindow` → 还原窗口位置 → 自检调度或正常启动 → 检查更新（工具运行与自检不检查）。

### 3.2 窗口

- **主窗口不是框架 `Window`**：`src/Momoka.Shell/Windowing/HostWindow.cs` 用 `CreateWindowEx` 建 HWND，再挂 `DesktopWindowXamlSource` 岛。标题栏那 48 像素是自绘的，非客户区（系统三颗键）由 DWM 参与，所以拖拽、最大化、DPI 都要按 HWND 处理。
- **设置窗口是框架 `Window`**（`src/Momoka.Shell/Views/SettingsWindow.cs`），它的画布、标题栏和系统观察单独一套。
- **集成管线的视频画面**由 `src/Momoka.Shell/Windowing/CompositionVideoTarget.cs` 用 `SpriteVisual` + D3D11 合成交换链接进 XAML 视觉树。
- **`PlayerPage` 是外壳的兄弟 `UserControl`，不在 `ContentFrame` 里**。这是刻意的：播放层要盖住整窗、自己管标题栏与拖拽；导航栈里没有它。

### 3.3 日志与异常

`Log` 是静态入口，正常启动写文件（`logs/`）并保留最近 1000 行在内存里给诊断页。未处理异常分两路：`AppDomain.UnhandledException` 记错误，`TaskScheduler.UnobservedTaskException` 记警告后 `SetObserved()`（图片与播放都有没人 await 的长任务，不让终结器线程掀掉进程）。

### 3.4 命令行开关分三类

| 类别 | 例子 | 说明 |
| --- | --- | --- |
| 普通启动也在用 | `--maximized`、`--screen` | 不影响「这是工具在跑」的判定 |
| 工具/截图 | `--show-library`、`--show-settings`、`--show-menu`、`--show-osd`、`--hide-cursor`、`--play`、`--theme`、`--dump-ui` | 让某一屏停在屏上，好拍照或观察；`StartupOptions.Tooling` 为真时不注册系统通知、不检查更新 |
| 验证 | `--self-check`、`--probe-shell[=inspect]`、`--probe-subtitles`、`--probe-composition`、`--probe-cursor`、`--probe-player-motion`、`--probe-resize[-manual]`、`--navigation-timing` | 各自独立运行，不互相混用 |

开关全集与组合限制见 [开发与验证](开发与验证.md)；`--show-menu`、`--show-osd`、`--hide-cursor` 与 `--self-check` 不能混用。

## 4. 组合根与依赖

`ShellServices.Build` 建 `ServiceProvider`，开 `ValidateOnBuild` 与 `ValidateScopes`：漏注册的依赖在启动时就报错并点名，而不是等到某个页面第一次用到时变成空引用。容器必须在 UI 线程上建，`IUiDispatcher` 在那一刻捕获 `DispatcherQueue`。

容器里的东西几乎都是单例，按职责分四组：

| 组 | 关键对象 | 说明 |
| --- | --- | --- |
| 地基 | `AppPaths`、`ISecretProtector`、`SettingsStore`、`AppSettings`、`SettingsService` | 设置只加载一次、原地编辑；两个实例会让一页的修改在另一页看不见 |
| 服务端 | `EmbySession`、`CredentialVault`、`DeviceIdentity`、`EmbyImageStore`、`ServerCapabilities` | 会话按「服务器账号」分来源，缓存有磁盘预算 |
| 播放 | `PlaybackService`、`PlaybackPlanner`、`PlaybackBackendFactory`、`AudioDeviceCatalogue`、`ShaderGroupResolver` | 后端按「每次播放新建」交给服务，切设置下一次起播就生效 |
| 界面 | `ShellPage`、`IShellActions`、`PlayerViewModel`、`MusicPlaybackViewModel`、`PlayerToolsController` | `ShellPage` 同时注册为 `IShellActions`，保证外壳动作不会指向另一棵隐藏视觉树 |

**`PlayerViewModel` 是唯一注册进容器的页面视图模型**：片子要在用户翻库时继续放，状态必须比导航活得久；它的依赖也最多，正好是 `ValidateOnBuild` 要抓的那类。其余页面默认自建视图模型，通过 `Attach(...)` 接收服务与身份。

`PlaybackService` 拿的是 `Func<IPlaybackBackend>` 而不是实例，所以「内置 libmpv / 外部 mpv.exe」是每次播放的选择，不是架构承诺。

## 5. 设置与本地数据

### 5.1 数据目录

`src/Momoka.Core/Infrastructure/AppPaths.cs` 决定布局，默认根是 `%LOCALAPPDATA%\Momoka`：

| 路径 | 内容 |
| --- | --- |
| `settings.json` / `settings.backup.json` | 设置文档与备份 |
| `cache/images/` | 海报、剧照、头像磁盘缓存（按图片 tag 做键，预算来自设置） |
| `cache/shaders/` | 着色器暂存 |
| `cache/danmaku/` | 弹幕缓存与内置凭据文件 |
| `logs/` | 运行日志；探针与自检各自在这里建本次运行目录 |
| `screenshots/` | 截图默认目录（可被设置改写） |
| `webview2/` | 内嵌网页控制台的用户数据目录 |

改名历史留下的旧目录由 `AppPaths.PriorRoots` / `LegacyDefaultRoot` 描述，启动时迁移。`ResolveProfile()` 用来找「哪份目录里真的有 `settings.json`」——自检和需要读生产配置的地方都走它，不假定就是默认目录。

### 5.2 设置文档

`src/Momoka.Core/Configuration/AppSettings.cs` 一个类装下全部设置，顶层分区：

`Servers`（服务器与账号）、`Mpv`（后端、管线、自定义配置）、`Playback`（报告、续播、阈值、轨道偏好、字幕模式）、`Video`（输出、HDR、着色器档位）、`Audio`、`Shaders`、`Ui`（主题、字号、缓存预算、主页行）、`Trailer`、`Shortcuts`、`Danmaku`、`SubtitleTranslation`、`PlayerTools`、`MoviePilot`、`LocalMedia`。

几条与实现绑定的规则：

- **`SchemaVersion` + `SettingsMigration.Normalize`**：读旧文件时补齐缺省、清掉退役字段、把越界值夹回合法范围。旧字段被默认序列化选项忽略，下次保存自然消失——不需要写删除逻辑。
- **保存是原子的**：`SettingsStore` 写临时文件再替换，`SettingsSaveQueue` 把连续修改合并成一次落盘；设置页的「延迟保存」走 `ISettingsService`，由 UI 队列调度。
- **隐藏/不可用不清空偏好**：能力恢复后原值还在（这条同时是界面规则，见第 9.5 节）。

### 5.3 凭据

- Emby/Jellyfin 令牌与密码用 DPAPI 加密后存在账号档案里（`ProtectedAccessToken` / `ProtectedPassword`），加解密只经 `ISecretProtector`。
- MoviePilot 与弹幕凭据各有自己的小存储，不硬塞进 `CredentialVault`（后者是给 Emby 账号档案用的）。
- **令牌不进 URL、不进命令行、不进日志、不进探针报告**。日志里的 URL 会去掉 query（`EmbyHttp.Redact`），但脱敏不能代替传递边界——真正的边界在播放传输层（见 7.3）。

## 6. 服务器协议层

### 6.1 共享传输

`src/Momoka.Core/Emby/EmbyHttp.cs` 是唯一发 HTTP 的地方：逐请求设置认证头（不动 `DefaultRequestHeaders`，否则并发取图会互相抢）、超时、重定向策略、错误翻译、下载与 `.part` 清理。异常层次区分「连不上 / 认证失败 / 令牌过期 / 服务端拒绝」，调用方按类型分支，不靠字符串匹配。

`EmbyServerAddress.Normalize` 只在一处归一基址；`EmbyUrl` 里的相对路径因此不带产品前缀。把 id 拼进路径前要过守卫（拒绝 `.`、`..` 和含 `/ \ ? #` 的段），再转义。

### 6.2 四套服务的差异

| 关注点 | Emby | Jellyfin | 飞牛影视 | Plex |
| --- | --- | --- | --- | --- |
| 基址 | 恒以 `/emby/` 结尾 | 根或反代子路径 + `/` | 独立端点与签名 | 服务器直连 + plex.tv 账号 |
| 认证 | `X-Emby-Authorization` + `X-Emby-Token` | `Authorization: MediaBrowser`（令牌是同一头的属性） | 登录换令牌 + 请求签名 | `X-Plex-Token` |
| 用户作用域 | 路径带 `{userId}` | 12.x 改由令牌决定，需要时作 query | 自有模型 | 自有模型 |
| 实时通知 | `/emby/embywebsocket` | `/socket`（另有应用层 `ForceKeepAlive`） | 任务轮询（`FnNasTaskWatch`） | `PlexRealtimeProtocol` |
| 片头片尾 | 章节上的 `MarkerType` | 10.10+ `GET /MediaSegments/{itemId}` | 自有字段 | 详情请求带 `includeMarkers=1` |
| 实测状态 | 4.10.x 通过 | 10.10.7 通过，12.x 未实测 | 0.9.8 / 0.8.43 通过 | 未实服核对 |

协议细节与逐条路由对照在技能里：[Emby](../.claude/skills/momoka-emby-api/SKILL.md)、[Jellyfin](../.claude/skills/momoka-jellyfin-api/SKILL.md)、[飞牛影视](../.claude/skills/momoka-fnnas-media-api/SKILL.md)、[Plex](../.claude/skills/momoka-plex-api/SKILL.md)；功能边界见 [Jellyfin 支持](Jellyfin支持.md)、[飞牛影视](飞牛影视.md)、[Plex 支持](Plex支持.md)。

### 6.3 会话、多账号与能力

- `EmbySession` 持有所有在线来源；每个来源一个 `EmbySessionScope`，固定「哪台服务器、哪个账号」。换默认管理账号不影响已捕获的作用域，退出该账号才撤销。
- 发起请求时通过作用域取该身份的最新令牌，而不是拿一份过期快照。作用域的生命周期参与播放的准入与撤销：身份被撤销要能把准备中的播放停掉，且只停一次。
- 聚合模式（默认关）允许多个账号同时在线，主页与搜索按来源聚合；同一台服务器的多个账号仍算一台服务器。见 [多服务器与多账号](多服务器与多账号.md)。
- 能力判断集中在 `ServerCapabilities` / `ServerAccess`。**管理员标记在 Emby 上常态是 `null`**（登录只对 Jellyfin 读 `User.Policy`），所以管理能力一律走「未知→放行，只有明确 `false` 才拒绝」，不要写 `IsAdministrator == true`。
- 页面的数据请求：视图模型捕获当前的 `EmbySessionScope`，经 `EmbyClient` 走 `EmbyHttp`；结果回来先比对作用域与页面代，身份已换或页面已离开就丢弃，不把旧账号的数据画进新页面。

### 6.4 实时刷新

`EmbyRealtimeConnection` 被 Emby、Jellyfin、Plex 共用：握手不带凭据进 URL，重连按 1/2/4/8/16/30 秒退避，离开主页或来源退出即取消。只有 `LibraryChanged` 会唤醒主页的媒体比对（比较前 24 个条目的 id 与顺序），播放/会话/用户数据消息不会触发整页刷新。主页没有周期性轮询兜底，断线期间错过的事件没有补发保证。细节与实测记录见 [媒体库实时更新](媒体库实时更新.md)。

## 7. 播放

播放是这套程序最复杂的部分，核心思路是：**把「怎么播」做成可测试的决策，把「谁来播」做成可替换的接缝**。

### 7.1 接缝与实现

| 角色 | 类型 | 职责 |
| --- | --- | --- |
| 接缝 | `IPlaybackBackend` / `IPlaybackHandle` | 上层只看到 `PlaybackRequest` 进、`IPlaybackHandle` 出 |
| 内置后端 | `LibMpvBackend` | 进程内加载 `libmpv-2.dll`，按管线决定合成呈现还是自建窗口 |
| 外部后端 | `MpvProcessBackend` | 用户自己的 `mpv.exe`，独立窗口，命名管道 IPC 驱动 |
| 选择 | `PlaybackBackendFactory` | 每次播放按设置新建后端 |
| 决策 | `PlaybackPlanner.Plan(ticket, connection)` | 算出 URL、头、轨道、着色器组、续播位置、截图目录 |
| 执行 | `PlaybackService` | 一次播放从开始到结束，并在过程中向服务器报告 |

`PlaybackPlanner` 刻意不碰进程与套接字，所以整套决策能在单测里断言。新增决策应放进 planner 或它调用的纯函数，不要塞进后端。

`IPlaybackHandle.HasControlChannel` 回答「控制通道真的开了吗」，不是「这是不是控制型句柄」——外部 `mpv.exe` 的句柄永远是控制型。两者混淆过一次，结果把「默认 100 音量、未静音」当成真实读数报给了服务器。

### 7.2 两条呈现管线

内置后端有两种画面呈现方式，设置里叫「视频管线」：

| | 集成（Integrated） | 独占（Standalone） |
| --- | --- | --- |
| 画面 | 合成交换链接进 XAML（`SpriteVisual`） | mpv 自建原生窗口，无边框窗口化全屏 |
| 控件 | Momoka 自己的播放层（`PlayerPage`） | 随包 uosc（`assets/mpv-ui`） |
| 图形接口 | 锁 `d3d11` + `gpu-context=d3d11` + `d3d11-output-mode=composition` | 跟随设置页「图形接口」，默认 `vulkan`（`gpu-context=winvk`） |
| 渲染器 | 两条都锁 `vo=gpu-next`，Required 失败即中止，不回退 | 同左 |

管线的最终契约由 `LibMpvPipelinePolicy` 在 planner 之后强制写入：先保留普通选项的次序（含重复项与列表操作），去掉客户端自己拥有的渲染/输入选项，再追加本管线的必需项。集成模式下「图形接口」不是设置，是那张交换链的物理前提。

### 7.3 凭据边界（最容易改坏的一处）

原生播放器**从不拿到服务器凭据**：

- `EmbyUrl.Stream` 拼的是 `Videos/{id}/stream{ext}?Static=true&MediaSourceId=…`，不带 `api_key`；`Static=true` 要求服务器原样吐文件，本程序不做转码决策。
- `PlaybackHttpTransport` 为每个文件在本机随机端口开一个回环服务，把受控的资源映射成匿名 URL；认证头只在 .NET 这一侧逐请求附加。
- 内置与外部后端都只收到匿名回环地址，native 的 `http-header-fields` 与 `http-proxy` 被清空。
- 同源重定向保留请求头，离开初始来源后整条链都不再带认证；嵌套清单（m3u/m3u8/mpd 等）直接拒绝，避免相对路径把回环服务变成开放代理。
- 外部后端起播前仍要核对 IPC 服务端 PID，资源不进进程参数。

认证的 HLS/DASH 与嵌套播放列表**不支持**：识别到扩展名、内容类型或明文特征就失败，而不是把凭据还给绝对地址。上游那一腿用 .NET 的系统代理与证书校验，mpv 自己的代理/证书选项不再配置它。

### 7.4 生命周期与报告

- `PlaybackService.Lifecycle` 管待处理请求、当前尝试与保留的同窗句柄。「起播取消」和「运行期寿命」是两件事：换片可以取消尚未建立的后端，但不能顺手掐掉一个兼容的正在播放的句柄。
- **`_generation` 是换片的边界**：每次换片自增，所有异步回调回来时先比对，不匹配就丢弃自己。上一集的迟到结果落进新一集，是这块最容易犯的错。
- **取消不是错误**：停止、关闭、换集都会取消在途请求，都不该弹错误提示。
- 报告走 `Sessions/Playing`、`.../Progress`、`.../Stopped` 三条，共用一种请求体（服务器会忽略不认识的字段）。`EventName` 是 `timeupdate` / `pause` / `unpause`；`PlayMethod` 恒为 `DirectStream`。周期由 `ProgressReportIntervalSeconds` 决定，夹在 1–60 秒。
- 续播来自条目自己的 `UserData.PlaybackPositionTicks`，并且只有进度落在 0.1%–99.5% 之间才算「有续播点」。
- 标记已看有两条阈值：全局 `MarkWatchedPercent`（默认 90）与国漫 `DonghuaMarkWatchedPercent`（默认 85）；自然播完无条件算已看。`MarkedWatched` 反映的是写回成功，不是「决定要标」。
- 音量与控制通道：`VolumeLevel` 需要「通道已开 + `VolumeKnown` + 有限值」三者同时成立，否则为 `null`；初始的 100 绝不能冒充读数。

### 7.5 轨道、字幕选择、章节与跳过

这些都是 Core 里的纯函数，改之前先读它们自己的注释：

- `TrackSelection.Resolve` 选音轨：按语言列表顺序取第一条匹配语言，再按 `AudioFormatRules` 排序，最后在同档里偏向默认轨。**语言列表为空表示不限语言**，仍然套格式规则。
- `SubtitleChoice` 区分「本片没有合适字幕，交给 mpv 自己按 `slang` 匹配」与「明确不要字幕（`--sid=no`）」。把这两种合成一个可空值，是 bug 不是简化。
- `EpisodeNavigation.Step` 解析上一集/下一集，走的是整部剧按播出顺序的列表（含带日期的特别篇），不缩到当前季。
- 章节有两份且都对：**屏幕上以 mpv 的 `chapter-list` 为准**（改封装过的文件会和服务器扫描结果不一致），但章节缩略图按 Emby 的索引取。
- 跳过片头片尾：优先用服务器给的数据（Emby 的 `MarkerType`、Jellyfin 的 `MediaSegments`、Plex 的 `Marker`），再用播放器章节里不重叠的区间补；服务器已经给过的类型不会被播放器数据替换。Jellyfin 的章节没有类型，所以它的服务端一半只存在于媒体段里。

### 7.6 播放器外壳

`PlayerViewModel` 是播放状态的汇合点：起播、换集、队列、字幕/音轨选择、音量、菜单快照、输入归属都在这里。`PlayerPage` 是它的视图，按功能拆成多个 partial（`PlayerPage.Chrome/Input/Menus/Queue/Timeline/...`），不要依赖固定清单。

两条与性能有关的约定：

- **集成页在屏上时，10 Hz 计时器要一直跑**：它驱动时间轴合并 seek、「跳过」提示和输出尺寸落定，也负责指针静止后藏光标。`ChromeReveal.Pending` 变 false 只说明浮层收完了，不代表可以停表。
- **不要每个 tick `new` 东西**：每秒重建 `TextBlock`、`FontFamily`、`Border` 会累积成可感知的 GC 压力，复用已有元素。

菜单用 `VideoMenuSnapshot` 的值（`snapshot-id:index`）而不是裸行号，换片时丢弃菜单与待处理按键。字幕拖放、延迟点击、滚轮调速都绑定 `InteractionContext`（当前播放尝试 + 代 + 条目），旧交互不能落到新文件上。

### 7.7 自定义 mpv.conf

默认播放走 `--no-config` / `config=no`。内置后端可以选「自定义 mpv.conf」：`MpvCustomConfig` 会暂存所选文件及其 include、展开 `~~/`、把宿主自己管的传输/日志/历史/脚本/窗口契约选项从每个 profile 里剔掉，剩下交给 mpv 解析；随后本程序再套自己的界面、单文件状态与管线契约。

显隐按能力走：**只有内置后端 + 独占模式可用**；集成模式下这一项固定为关、以只读文字显示有效值；外部后端整张卡收起（那时读的是 `mpv.exe` 自己的配置）。自定义会话在换集时重启，以便重新加载条件与文件改动。

### 7.8 输出设置

音频（设备枚举/核对/回退、声道、直通、响度、延迟、音量记忆）、视频（HDR/杜比语义、图形接口、画面填充）、着色器（四档 × 真人/动画 × 显卡档、链互斥、运行期切换）各有专门技能： [音频输出](../.claude/skills/momoka-audio-output/SKILL.md)、[视频输出](../.claude/skills/momoka-video-output/SKILL.md)、[着色器](../.claude/skills/mpv-shader-quality/SKILL.md)。三者最终都汇进 `MpvOutputOptions` / `MpvBaseline` / `ShaderGroupResolver`，再由 `LibMpvPipelinePolicy` 收口。

## 8. 字幕、弹幕与实时翻译

### 8.1 字幕

- 外观由 `MpvOutputOptions.SubtitleAppearance` 一处产出（字体、字号、粗体、颜色、描边、阴影、底板等），`Build` 再补两条只能起播时定的（`sub-codepage`、画面拉伸）。
- **`sub-ass-override` 默认是 `scale`**：ASS/SSA 字幕会忽略字体、字号、颜色、描边、阴影与底板，只有 `sub-scale` 生效。设置里「外观应用范围 = 强制」才发 `force`。PGS/VOBSUB 是图形字幕，两条路都不吃这些设置。
- 播放中改一行也要推给正在放的片子：`PlaybackService.ApplySubtitleStyleAsync` 会遍历选项名，对设置里已不再指定的项向 mpv 问默认值——运行中「不发」意味着「保持上一分钟发的那份」。
- 字幕编码默认「自动识别」；指定代码页会关掉 mpv 的探测，曾把 Big5 繁体读成简体。
- 同窗换集要自己重置主字幕可见性、次字幕选择/可见性/延迟/位置/样式，裸 mpv 不会自动重置。
- 服务器字幕管理：Emby 的搜索/下载/删除要绑定打开对话框时捕获的 `MediaSourceId`；Jellyfin 的本地字幕上传用版本条目 id 路由，并要求显式的字幕管理授权。两者不要互相套用路由。详见 [字幕技能](../.claude/skills/momoka-subtitles/SKILL.md)。

### 8.2 弹幕

- 来源两种：弹弹play（内置凭据，只有这一种，自定义 AppId/AppSecret 已退役）与用户自部署的 `danmu_api`。「两者都开」是选择模式，但每条请求仍只属于一个 `DanmakuSource`，两源的 `episodeId` 可以重号。
- 匹配、聚合、发送在 `Core/Danmaku`；渲染走独立 Lua 图层（`assets/mpv-ui/scripts/momoka_danmaku.lua`），不占主/次字幕轨；发送输入框在 uosc 侧。
- 设置与快捷键说明见 [弹幕与快捷键](弹幕与快捷键.md)，协议与上游核对见 [弹幕技能](../.claude/skills/momoka-danmaku/SKILL.md)。

### 8.3 实时字幕翻译

- 默认关闭；服务三选一：谷歌、微软、兼容 OpenAI。需要用户自备密钥，启用后会把文字字幕外发。
- 译文本走独立 Lua OSD 图层（`momoka_subtitle_translation.lua`），保留原字幕；`SubtitleTranslationRuntime` 一次只发一个请求，过期线索取消在途请求，缓存只在内存、有上限，字幕与密钥都不进诊断。
- 功能说明与隐私边界见 [实时字幕翻译](实时字幕翻译.md)。

## 9. 界面体系

### 9.1 外壳

`ShellPage` 是一整窗的根：顶上 48 像素自绘 chrome（左端是主页/收藏/设置/搜索/返回/前进，正中是够宽才出现的搜索框，右端是账号与系统三颗键），下面是 `ContentHost` 画布与 `ContentFrame` 导航栈。登录卡是浏览容器的兄弟而不是 `Frame` 里的一页：一个窗口、一个主题根、一个 `XamlRoot`，退出登录时显示一棵已经建好的树。

两种外壳形态由 `UiSettings.EnableImmersive` 决定：

- **侧栏（默认，`EnableImmersive=false`）**：`NavigationView` 承载导航（主页/收藏/媒体库与订阅/设置；库项与两条订阅排在同一张名单里，次序取设置里的“媒体库顺序”，没有单独的“订阅”分区），页面让开栏宽；chrome 左端换成「返回 · 折叠」，主页/收藏/设置让给栏里的入口，同一页不出两个同样的入口。栏宽默认 256 DIP，可拖右沿改（180–480），窄窗按窗宽再收一档但不改写偏好；开合默认按窗宽定（`SidebarWideThreshold = 1008`），用户手动折叠过就记住那一档。
- **沉浸（`EnableImmersive=true`）**：chrome 一行浮在页面上，页面从窗口最左边开始；主页上是铺满的剧照。开启沉浸不影响外观偏好，只换导航形态。

标题栏那 48 像素里的可点元素都要「挖洞」（`ReportTitleBarHoles`），否则按下去变成拖窗口。

### 9.2 页面与视图模型

- 页面自建 VM，`Attach(...)` 接收依赖与身份；离开时释放自己持有的 CTS、订阅与计时器。
- 绑定到 `ItemsSource` 的集合默认保持稳定、原地更新；小改动不全量重建，整体刷新注意选择与滚动位置。
- 会话相关页面实现 `ISessionScopedPage`，身份切换时由外壳通知重载，而不是靠页面自己猜。
- 异步分页、会话切换、设置页重进、启动与报告完成这几类寿命问题，见 [页面寿命参考](../.claude/skills/momoka-winui-shell/references/page-lifetimes.md)。

### 9.3 主题与材质

- 五套固定深色（薄荷影院、纯黑、午夜、石墨、紫夜）+ 跟随系统；`UiThemes.Compose` 把「色板 + 选择模式」合成为实际配色（浅色档用系统浅色），`ThemeHost.Apply(UiSettings)` 再按整份界面设置套上主题色与透明效果。
- `Theme/Palette.xaml` 只负责第一帧，真正生效的是 `UiThemes` 推出来的表；`ThemeHost` 在构造时设置 `RequestedTheme`，换主题时再改，并在系统主题/强调色变化后重算。
- 材质：主窗口与设置窗口整块 Mica 画布（`EgCanvasBrush`），卡面按需带局部 `MicaKind.Base`；详情页与订阅详情的「简洁模式」**不挂页面级局部材质**，底就是外壳画布那一层。判据由主测试里的 `MicaMaterialTests` 源码契约钉住。
- 高对比度用系统角色；浅色档复用系统浅色配色。材质的放置、回退与像素判读见 [材质参考](../.claude/skills/momoka-winui-shell/references/materials.md)。

### 9.4 弹窗

- 所有 `ContentDialog` 派生类型都要在 `Theme/Styles.xaml` 里有一行隐式样式，`BasedOn` 到 `EgDialogSurfaceStyle`；主测试里的 `DialogChromeTests` 会逐个派生类查样式链。
- 点弹窗外面关闭由 `src/Momoka.Shell/Views/DialogDismiss.cs` 的附加属性 `ClosesOnOutsideClick` 实现，挂在上面那份样式上。判「外面」取模板里 `BackgroundElement` 的矩形，关闭走 `Hide()`，`Closing` 里的拦截照样生效。
- `Flyout` / `MenuFlyout` 保留平台行为；交互 `Popup` 开 `IsLightDismissEnabled`。
- WinUI 模板事实：标题是内容滚动区里一颗左对齐、按内容定宽的 `ContentControl`，`TitleTemplate` 撑不满宽度；三个按钮文本全空时整条命令区（含 24 DIP 上边距）收起。要在标题行右侧放按钮，只能把 `Title` 换成自己搭的一行。

### 9.5 能力显隐

政策在 [CLAUDE.md](../CLAUDE.md#功能可用性与显隐)，实现约定在 [Shell 技能](../.claude/skills/momoka-winui-shell/SKILL.md#capability-dependent-visibility)。要点：

- 当前配置下不可用或不会生效的功能**自动隐藏**（按钮、菜单、设置、从属说明、空白一起收起），不用置灰代替。
- 状态变化、重新进入、导入设置、恢复默认后当场重算；隐藏不清空偏好。
- 界面隐藏不替代命令与服务层的能力/身份/权限检查。
- 搜索页来源栏是明确的例外：四个来源始终显示且不改选，不可用时显示恢复说明并阻止请求。

### 9.6 动效与性能约定

- 默认用平台动画与系统材质；自绘动效要可打断，且不阻塞输入。
- 图片渐进显示、封面关联动画等都在既有 helper 里（`ImageArrivalFade`、`ConnectedMotionReceipt`、`CardDetailTransition`），不要另起一套。
- 自适应版式用 code-behind（`SizeChanged` + `Grid.SetRow/SetColumn` + 列宽），判据用**内容区**宽度；`AdaptiveTrigger` 在本项目实测不生效。

| `--probe-shell[=inspect]` | 驱动真实窗口跑外壳用例，按 `--probe-section` 选分区（`shell`/`settings`/`library`/`moviepilot`/`playback`/`materials`/`music`/…） | 分区运行只覆盖所选区域；报告与 `shell-probe-scope.txt` 会写明未执行区域 |
| `--self-check` | 在独立运行目录、用设置副本跑一批窗口级检查，输出报告 | 会登录真实账号、读真实库，**不是离线证据**；与完整 Core 套件共用同用户互斥锁 |
| `tools/selfcheck-diff.ps1` | 按检查名与状态比对本次报告与基线 | `-Log` 只证明那份报告里写了什么，不证明当前代码跑过 |
| `--probe-composition` / `--probe-cursor` / `--probe-player-motion` | 隔离的本地播放/指针/动效探针 | 只覆盖集成管线；不代表独占窗口、uosc、同窗换片或外部 mpv |
| `tools/shot.ps1`、`--dump-ui` | 真实屏幕截图 / 页面 PNG + 视觉树 | `--dump-ui` 不合成 Mica；属性正确不等于像素正确 |

判读规则：证据只对跑它的那份代码有效；失败、未执行与跳过都不能算通过；环境造成的红保留在报告里，不用重跑或改基线洗绿。

## 12. 构建与发布

### 12.1 环境

- **.NET 10 SDK**，版本以 [global.json](../global.json) 为准。本机装的就是 `global.json` 钉的那一版，但它不在 PATH 上（PATH 上的 `dotnet` 是 8.x），所以命令统一写 `$HOME/.dotnet/dotnet.exe`。
- 本地播放与发布需要匹配的 x64 `libmpv-2.dll` 放在工作树根，由 Shell 工程链接进输出并随发布拷贝。该文件不入库，新工作树要单独提供。
- Windows 10 1809+ / x64；「网页控制台」页需要 WebView2 Runtime。

### 12.2 常用命令

```bash
# 还原、构建、空白检查（闸门 1 的三条，与开发文档一致）
"$HOME/.dotnet/dotnet.exe" restore ./Momoka.sln
"$HOME/.dotnet/dotnet.exe" build ./Momoka.sln -c Release --no-restore
"$HOME/.dotnet/dotnet.exe" format whitespace ./Momoka.sln --verify-no-changes --no-restore

# 发布到本树 artifacts/publish/win-x64 并刷新桌面快捷方式
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish.ps1 -NoArchive -Shortcut

# 安装包
powershell -NoProfile -ExecutionPolicy Bypass -File tools/installer.ps1 -SkipPublish
```

日常小改不用跑全方案构建：改 Shell 就只编 `./src/Momoka.Shell/Momoka.Shell.csproj`，再编并运行受影响的测试工程。

`publish.ps1` 的常用开关：`-NoArchive`（不压缩）、`-Shortcut`（刷新 `.lnk`，**不传就不刷新**）、`-SkipPublish`（拿现成发布目录打包）、`-Msix`、`-Store`（商店上架包，隐含 `-Msix`，与签名互斥）、`-Sign` / `-CertPath` / `-Timestamp`。完整参数与副作用以脚本头部注释为准。

### 12.3 发布目录与快捷方式

- 发布目录：本树 `artifacts/publish/win-x64`。
- 快捷方式：主树 `Momoka.lnk`，临时分支 `Momoka-<分支标识>.lnk`，互不覆盖；分支树的发布不能指向主树。
- 商店包：`artifacts/Momoka-<版本>-win-x64-store.msix`，不签名，由 Partner Center 用预留身份重签；包身份只在 `tools/store-identity.json` 一处。

### 12.4 随包载荷的闸门

`assets/mpv-runtime/approved-payload.json` 固定随包 mpv 载荷（`mpv-ui`、`libmpv-2.dll` 及其依赖）的大小与哈希，发布前由 `tools/verify-mpv-payload.ps1` 校验。**改 `assets/mpv-ui/**` 或 `THIRD-PARTY-NOTICES.md` 必须在同一次提交里重钉这份清单**（不动 `approvalId`），否则发布直接失败。依赖与运行时包的独立清单见同目录的 `approved-runtimepack.json` / `approved-dotnet-runtimepack.json`。

## 13. 已知限制与产品例外

### 13.1 功能边界

- **Plex 没有实服证据**：连接、浏览、清单写入与播放都只有协议级离线测试。
- **Jellyfin 12.x 只做了协议对照**，实测通过的是 10.10.7；用户作用域路由在 12.x 已改成令牌决定 + query，改路径前先按版本分支。
- **飞牛影视的管理写入未验证**；播放与库读取已实测。
- **认证的 HLS/DASH 与嵌套播放列表不支持**，识别到就失败，不会退回「把凭据给原生播放器」。
- **播放探针只覆盖集成管线**：独占窗口、uosc、同窗换片与外部 mpv 的运行时行为没有自动证据。
- **真实播放会改观看历史与续播点**：真实服务器播放属于需要单独授权的验证档位，不能拿真实库当夹具。

### 13.2 产品例外（改动前先确认）

- 五套固定深色 + 跟随系统，强调色可选但不支持导入主题文件。
- 所有弹窗点外部关闭；`ContentDialog` 必须挂到 `EgDialogSurfaceStyle` 的样式链上。
- 影视库按 Emby / Jellyfin / 飞牛分别实现与验证；音乐库统一界面与底部播放栏。
- 搜索页来源栏始终显示、不改选，与一般「不可用就隐藏」相反。
- 设置里的「自定义 mpv.conf」只有内置后端 + 独占模式可用，集成模式只读固定关。

这些是已确认的产品选择，不是待修的缺陷；要改先按 [CLAUDE.md](../CLAUDE.md#winui-官方优先与偏离确认) 的流程确认。

# 媒体库网页端按钮核对（Emby 4.10.1.0 / Jellyfin 10.10.7 / 飞牛 0.9.8）

- 日期：2026-11-01
- 对象：`work/媒体库网页端源码/`（三台服务器网页端的浏览器另存，共 7 个页面）
- 目的：查清网页端库页有哪些按钮、各自在什么条件下出现，对照本项目（Momoka）现有实现，列出缺失项与判断依据
- 结论摘要：**工具条、卡片浮层、条目菜单这一层已经复刻到位**；真正缺的是一组**能力型入口**（播放队列、多选批量、播放列表、从这里播放、条目媒体信息、转换、取消识别），外加库页载入失败那颗「重试」。评分、分享、从开头播放在网页端也不在库页，单列为 D 类

### 1.2 证据分三级（报告里每条结论都标了级别）

- **A（可执行源码，留档内）**：Emby 留档里存了 **168 个 JS 模块**（`_files` 目录）。按钮相关的几块全在：`videos.js`、`listcontroller.js`、`baselistcontroller.js`、`baseitemcontroller.js`、`itemmanager.js`、`shortcuts.js`、`multiselect.js`、`commandprocessor.js`、`tabbedview.js`。按键怎么绑、什么时候 `hide`、卡片菜单传哪些开关，都能逐行读到。
- **B（上游仓库源码）**：Jellyfin 留档只存到 500 KB 主包和一个 chunk，`itemContextMenu`、`multiSelect` 这些组件不在里面。本轮按 `jellyfin/jellyfin-web` 的 `v10.10.7` 标签补读 `src/controllers/list.js`、`src/components/itemContextMenu.js`、`src/components/multiSelect/multiSelect.js`。
- **C（只有渲染后的 DOM）**：飞牛。留档里两个 JS（5 KB + 15 KB）都不是主包，卡片上「⋯」展开后的菜单内容**核对不到**。

判断一律以源码为准；只有 DOM 的地方如实写「未核对」，不拿印象补。

## 2. 网页端库页按钮全清单

### 2.1 Emby 4.10.1.0

**工具条（`itemsViewSettingsContainer`）** —— 出处 `listcontroller.js` 的 `initButtons` 一段，配合留档 DOM。

| 按钮 | 做什么 | 出现条件（源码） |
| --- | --- | --- |
| 共 N 项 | 这一页的总数 | `enableTotalRecordCountDisplay !== false` |
| 播放 | 从头播这一页所有可播条目 | `supportsPlay()`：类型是 电影/单集/预告/音频/专辑/音乐视频/视频/照片（`baselistcontroller.js`） |
| 随机播放 | 打乱后播放 | `supportsShuffle()` 与播放同一条 |
| 添加到播放队列 | 把这一页塞进播放队列 | `supportsQueue()` 与播放同一条；**留档这两张库页的模板里没有这颗键**，哪些页面有未核对 |
| 排序 | 打开字段表，选中项右侧带方向箭头 | `supportsSorting()`：排序菜单非空 |
| 过滤器 | 打开筛选面板 | `getVisibleFilters().length > 0`，否则整颗 `hide` |
| 设置 | 打开视图设置（视图 / 图像大小 / 按合集分组 / 显示字段） | `supportsViewSettings !== false` |

两个细节值得记：① 每颗键都有**文字版和图标版两套**（`listTextButton-autohide` / `listIconButton-autohide`），窄屏自动换成图标；② 整条工具条在「没有一个键可用、也没开总数」时自己 `hide`。

**卡片浮层**（留档 DOM，`cardOverlayContainer`）—— 五件：

| 元素 | 标题（DOM 原文） | 说明 |
| --- | --- | --- |
| 复选框 | 多选 | 进多选模式的入口 |
| 播放 | — | 主按钮，圆角实心 |
| 已看开关 | 标记为已播放 / 标记为未播放 | 按条目当前状态换字 |
| 收藏 | 添加到 «收藏» / 从收藏移除 | 同上 |
| 更多 | 更多 | 打开条目菜单 |

**条目菜单**（`baseitemcontroller.js` 的 `getCommands`，条件取自同一函数）：

| 分组 | 菜单项（源码里的 id） | 条件 |
| --- | --- | --- |
| 播放 | 播放 `resume`、从开头播放 `playfrombeginning`、从这里播放 `playallfromhere`、随机播放 `shuffle`、立即混搭 `instantmix`、播放幻灯片 | 从开头播放要调用方传 `playFromBeginning`，库页卡片没传（见下） |
| 队列 | 添加到播放队列 `queue`、下一个播放 `queuenext`、从播放队列移除 `removefromplayqueue` | `playbackManager.canQueue(item)` |
| 归集 | 添加到合集 `addtocollection`、添加到播放列表 `addtoplaylist` | 条目类型与权限判定 |
| 状态 | 添加到收藏 / 从收藏移除、标记为已播放 / 未播放 | `canRate`、`canMarkPlayed` |
| 多选 | 多选 `multiselect` | `options.multiSelect && !tv` |
| 管理 | 下载 `download` / 下载到设备 `sync`、转换 `convert`、编辑元数据、编辑图片、编辑字幕、识别 `identify`、取消识别 `resetmetadata`、刷新元数据、扫描媒体库、合并版本、删除、分享 `share`、管理访问 / 离开共享 | 各自看权限、条目类型与服务器开关 |

**多选模式**（`multiselect.js`）：卡片勾选后，页头长出「✕ / 选中数量 / 几个主按钮 / ⋯」；主按钮与 ⋯ 里的项目**都是同一套 `getCommands`**，只是按「选中项是否全都允许」过滤（`itemcontextmenu.show({items, multiSelect:false, users})`）。

**库页卡片到底传了哪些开关**（`shortcuts.js`）—— 这是「菜单里定义了什么」与「库里真的看到什么」之间的那道门：

```
items:[item], play:true, queue:true, playAllFromHere:!item.IsFolder,
queueAllFromHere:!item.IsFolder, user, multiSelect:<列表渲染器的设置>, programInfo:true
```

所以库页卡片菜单上会有：播放、从这里播放（不是文件夹时）、添加到播放队列、下一个播放、添加到合集/播放列表、收藏、标记已看/未看、多选、下载、转换、编辑、识别、刷新、扫描、删除、合并版本、取消识别……**不会有「从开头播放」**（这个开关只有详情页传）。

**空态与失败态**：没有结果且带着筛选时，空态里给一颗**清除筛选**（`btnClearFilters`）；数据取失败时，错误块里给一颗**重试**（`btnRetryData`，`tabbedview.js` 的 `onDataFetchError`）。

**其它**：右侧字母条（`alphaPicker`，名称序 + 固定右侧）；卡片墙的左右滚动按钮。

Jellyfin 的库页有**两套工具条**，这点和 Emby 不一样。

**（a）list 页**（`list.html`，混合库、文件夹下钻都用它）—— 出处 `src/controllers/list.js` + 留档 DOM：

| 按钮 | 做什么 | 出现条件 |
| --- | --- | --- |
| 44 的 1-44 | 分页读数（`libraryBrowser.getQueryPagingHtml`） | 恒在 |
| 全部播放 `btnPlay` | 播这一页 | 父条目是 CollectionFolder 且不是「家庭视频」→ `hide`；文件夹页才出现 |
| 添加至播放队列 `btnQueue` | 塞进队列 | `playbackManager.canQueue(item)` |
| 随机播放 `btnShuffle` | 打乱播放 | 同播放，另外 `nextup` 页不显示 |
| 新建 `btnNewItem` | **打开播放列表编辑器建一张空列表**（`onNewItemClick` → `PlaylistEditor`） | 除「播放列表」库以外都显示 |

| 筛选 `btnFilter` | 筛选面板 | `getVisibleFilters().length` 为 0 时 `hide` |
| 更多 `btnViewSettings` | 图片类型（封面/横幅/光盘/标志/缩略图/列表）+ 显示标题 | 恒在 |

**（b）电影 / 剧集库根**（`movies.html` / `tv.html`，留档 DOM）—— 图标键只有「选择视图」（`btnSelectView`）、排序、筛选；两头各有一处差别：

| 页面 | 工具条 | 读数 |
| --- | --- | --- |
| 电影库（38 项） | 随机播放、选择视图、排序、筛选 | 「38 的 1-38」，一页装得下，没有翻页键 |
| 剧集库（142 项） | 选择视图、排序、筛选（**无随机播放**） | 「142 的 1-100」，带 `btnPreviousPage` / `btnNextPage`（首页时上一页 `disabled`） |

两页都没有播放、没有队列、没有新建 —— 它们是 `CollectionFolder`。

**卡片浮层**：只有两颗 —— 收藏（`emby-ratingbutton`，标题「加入收藏」）、更多（`data-action="menu"`）。**没有播放键**，点卡片本身进详情。

**条目菜单**（`src/components/itemContextMenu.js`，v10.10.7）：

| 分组 | 菜单项 | 条件 |
| --- | --- | --- |
| 播放 | 播放 `resume`、从这里播放全部 `playallfromhere`、停止播放 `stopPlayback`、清空队列 `clearQueue` | 后两个只在有播放器时 |
| 队列 | 加入队列 `queue`、下一个播放 `queuenext` | `playbackManager.canQueue(item)` |
| 条目 | 随机播放、立即混搭、多选 `multiSelect`（文案「选择」） | 多选只在卡片上、非 TV 端 |
| 归集 | 加入合集、加入播放列表 | `supportsAddingToCollection` / `supportsAddingToPlaylist` |
| 状态 | 标记为已播放 / 未播放 | `canMarkPlayed`（评分不在卡菜单里，见 §2.4 注） |
| 文件 | 下载全部、下载、复制流地址、删除 | `appHost.supports('filedownload')`、`CanDownload`、`CanDelete` |
| 管理 | 编辑元数据 / 图片 / 字幕 / 歌词、识别、**更多媒体信息**、刷新元数据、分享 | 各自权限（管理员、字幕管理、公开分享开关） |
| 播放列表内 | 从播放列表移除、移到顶部 / 底部、从合集移除 | 带 `PlaylistItemId` / `CollectionId` 时才出现 |

**多选**（`multiSelect.js`）：选中后页头一条「✕ / 选中数量 / ⋯」，⋯ 里是：全选、加入合集、加入播放列表、删除、合并版本（管理员）、标记已播放、标记未播放、刷新元数据。

**空态 / 失败态**：清除筛选（`btnClearFilters`）、重试（`btnRetryData`），与 Emby 同一套写法。

**两条边界**（读源码时容易看漏，写在这里免得被当成库页按钮）：① **评分**——`itemHelper.canRate` 只服务详情页的星级，卡菜单里没有这一条；② **分享**——`itemContextMenu` 里写的是 `options.share === true` 才出现（默认不带），库页卡片走默认参数时不会有它。Emby 那边分享是默认带上的（`!== false`），两家不同。

### 2.4 三家放在一起看

1. **库根有没有播放键，两家判法不同**：Emby 看条目类型的显示预设 —— `supportsPlay()` 对空预设返回真，所以混合内容库根（摆的是文件夹）照样有「播放 / 随机播放」；Jellyfin 明确对 `CollectionFolder` 关掉（list 页那句 `CollectionFolder && CollectionType !== Homevideos`），库根模板里电影库只留「随机播放」、剧集库连随机都没有。
2. **只有 Jellyfin 有队列键和「新建播放列表」**；Emby 的队列在条目菜单里（`queue` / `queuenext` / `removefromplayqueue`），工具栏那颗 `.btnQueue` 留档页上没有。
3. **多选两家都有**，入口不同：Emby 是卡片上的复选框，Jellyfin 是菜单里一条「选择」。
4. **空态清除筛选、失败重试两家都有**，写法几乎一样。
5. **只有 Jellyfin 有真翻页键**（`btnPreviousPage` / `btnNextPage`，一页 100 项）；Emby 是虚拟滚动 + 「共 N 项」，没有上下页。
6. **命名不统一**：Emby 叫「过滤器」，Jellyfin 叫「筛选」；Emby 叫「设置」（齿轮），Jellyfin list 页叫「更多」（⋯）。

### 3.2 卡片浮层（`PosterCard.xaml`）

| 按钮 | 做什么 | 出现条件 |

### 3.3 条目菜单（`ItemMenu.cs` + `ItemCommands*.cs`）

播放 / 继续播放、详细信息（不能播的条目是「打开」）、标记为已观看、标记为未观看、添加到收藏、取消收藏、从继续观看移除、添加到合集、下载、编辑元数据、修改封面、搜索字幕、识别、刷新元数据、重新扫描媒体库、打开所属剧集、查看遗漏集、管理版本（飞牛）、手动匹配（飞牛）、解除匹配（飞牛）、搜索其他版本 / 不同版本（MoviePilot、AniBT）、手动整理 / 智能整理 / 重新整理（MoviePilot）、媒体管理三个删除档（MoviePilot）、删除。

### 3.5 我们比网页端多出来的入口（不是缺失，列出来免得被当成「网页端也有」）

- **卡片直接播**：Jellyfin 的卡片浮层只有收藏 + 更多，播放要点进详情；我们给封面正中间一颗播放键。
- **卡片已看开关**：Jellyfin 卡片没有，Emby 有（`emby-playstatebutton`），我们跟随 Emby。
- **电影库的「播放」**：Jellyfin 的 `movies.html` 模板里根本没有 `btnPlay`（DOM 里连隐藏元素都没有），只有「随机播放」；我们在这一页两颗都给。
- **搜索的四个来源、账号筛选、查看遗漏集、飞牛的手动匹配 / 解除匹配、MoviePilot 与 AniBT 那一组**：网页端没有，属于本项目自己的东西。

## 4. 缺失清单

### A 类：两家网页端都有、本项目完全没有（缺的是能力，不只是按钮）

| # | 缺的按钮 | 网页端依据 | 本项目现状 | 用户会遇到的场景 | 量级 |
| --- | --- | --- | --- | --- | --- |
| A1 | 添加到播放队列 / 下一个播放 / 从队列移除 / 清空队列 | Emby `baseitemcontroller.getCommands` 的 `queue`／`queuenext`／`removefromplayqueue`（`canQueue` 条件）+ `commandprocessor` 的 `queue`／`queuenext`／`queueallfromhere`；Jellyfin `list.js` 的 `btnQueue` + `itemContextMenu` 的 `queue`／`queuenext`／`clearQueue`／`stopPlayback` | 全仓没有「播放队列」这个概念（只有本季自动连播） | 连着看几部片、边看边攒一个片单 | 大：要引入队列模型、播放器换片路径、三服务器上报差异 |
| A2 | 多选与批量操作（标记已看、收藏、加合集、删除） | Emby `multiselect.js`（卡片复选框 + 选中条 + 复用 `getCommands`）；Jellyfin `multiSelect.js`（菜单「选择」+ 全选/合集/播放列表/删除/合并版本/已看/刷新） | 没有任何多选 | 一口气把十集标成已看、批量清收藏 | 大：卡片加复选框、选中条、批量命令与确认 |
| A3 | 新建播放列表 / 加入播放列表 | Jellyfin `btnNewItem` → `PlaylistEditor`；`itemContextMenu` 的 `addtoplaylist`。Emby `addtoplaylist` | 无播放列表（只有飞牛的「播放列表文件」导入，是另一件事） | 把几部片攒成一张自己的片单 | 大：要服务器端建列表、条目增删、排序 |
| A4 | 从这里开始播放（播放全部从这条开始） | Emby `playallfromhere`，库页卡片调用方明确传了 `playAllFromHere: !item.IsFolder`（`shortcuts.js`）；Jellyfin `playallfromhere` | 只有整页「播放」「随机播放」 | 第 20 集开始往后连看 | 中：要按当前排序算出「这条之后」的清单 |
| A5 | 条目「媒体信息」 | Jellyfin `moremediainfo`（`item.MediaSources && options.moremediainfo !== false`） | 只有**播放器里**有媒体信息（`MediaInfoDialog` 从播放页调用），库里的条目没有入口 | 看一部片是什么码率、几条音轨 | 小到中：要取条目的 `PlaybackInfo`，复用同一张表 |
| A6 | 转换 | Emby `convert`（`canConvert`）；Jellyfin `canConvert`（需 `EnableMediaConversion`） | 无 | 转成另一个码率/容器留给手机 | 大：要轮询服务器任务、显示进度 |
| A7 | 取消识别（清掉刮削结果） | Emby `resetmetadata`（服务器 ≥ 4.8.0.30） | 无（有「识别」，没有撤销） | 识别错了想退回未识别 | 小：一次 DELETE/POST + 二次确认 |

### B 类：网页端有、本项目打了折

| # | 位置 | 差异 | 判断 |
| --- | --- | --- | --- |
| B1 | 库页载入失败 | 网页端在错误块里给「重试」；我们只有一条可关的 `InfoBar`，要退出重进页面 | **该补**，一颗按钮的事 |
| B2 | 飞牛工具条 | 网页端有「共 43 项」，按 2026-11-01 的用户令去掉了 | 有意差异，不算缺 |
| B3 | 工具条窄屏 | Emby 每颗键有文字版 / 图标版两套自动切换；我们是药丸换行 | 有意差异，桌面端窗口不会窄到那个程度 |
| B4 | 分页 | 网页端剧集库是「142 的 1-100」+ 上一页 / 下一页；我们滚动加载，读数是「142 的 1-50」随滚动增长 | 范式差异（桌面端滚动更自然），但**同一串读数的含义不同**：网页端说的是「这一页的区间」，我们说的是「已加载多少」。不写清楚会被读成「库里只有 50 项」 |
| B5 | 过滤器命名 | Emby 叫「过滤器」，我们叫「筛选」 | 与 Jellyfin 统一，可保留 |

### C 类：只在一家、不建议照抄

录制 / 取消录制（直播电视）、管理访问 / 离开共享（用户与共享库）、复制到剪贴板（API Key）、复制流地址、播放列表内上移下移、改库内容类型 / 重命名库、编辑歌词、停止播放与清空队列（跟着 A1 一起考虑，不单独做）。

理由同 `CLAUDE.md` 的功能显隐规则：这些要么依赖服务器开关（开了才有意义），要么是网页面板才有的管理动作；在桌面端摆一颗常年不可用的键，不如不做。

### D 类：网页端有，但不算「库页缺按钮」（供你判断要不要做）

| 项 | 实际情况 | 结论 |
| --- | --- | --- |
| 从开头播放 | Emby 的菜单构建里有 `playfrombeginning`，但**库页卡片的调用方（`shortcuts.js`）只传了 `play`／`queue`／`playAllFromHere`／`queueAllFromHere`／`multiSelect`／`programInfo`，没传这个开关** | 抓到的两张库页卡片菜单里不会有这一条；它是详情页的事。我们要在库页给，属自主决定 |
| 评分 | Jellyfin 的 `canRate` 只服务**详情页**的星级，卡菜单里没有这一条 | 要做得放在详情页，不是库页 |
| 分享 | Emby 默认带（`!== false`，看 `canShare`）；Jellyfin 要调用方显式传 `share: true` 才出现 | 库页要不要给，取决于你用不用服务器的公开分享 |
| 上一页 / 下一页 | 只有 Jellyfin 有（一页 100 项）；Emby 是虚拟滚动 | 我们已经选了滚动加载，这是范式不是缺件 |

## 5. 缺失的判断依据

1. **以源码里的条件为准，不以截图为准。** 截图只证明那一刻。三个反例正好都在留档里：
   - `emby/电影.html` 整条工具条不存在 —— 不是没有，是这页抓的是 `tab=suggestions`，建议页本来就没有工具条；
   - Jellyfin 混合库根上 `btnPlay`／`btnQueue`／`btnShuffle` 都带 `hide`，进文件夹才出现（`list.js` 里 `CollectionFolder && CollectionType !== Homevideos` 那两段）；
   - Emby 的 `btnFilter` 在 `getVisibleFilters()` 为空时 `hide` —— 混合内容页那颗就是 `hide` 状态。
2. **「隐藏」不等于「不存在」。** 所以本报告把「源码里绑定了、但留档页没显示」的（例如 Emby 的 `.btnQueue`）单列成「未核对」，不写成缺失，也不写成已有。
3. **两家都有的才算「应有」。** 只出现在一家的能力（录制、管理访问、复制流地址）放到 C 类；网页端有但不在库页的（评分、分享、从开头播放）放到 D 类，都不混进 A 类，免得拿一家的实现当普适标准。
4. **本项目侧按代码判，不按印象判。** 每条「没有」都是在 `src/Momoka.Core` 与 `src/Momoka.Shell` 里搜过对应词（「播放队列」「播放列表」「instantmix」「从头播放」「分享」「转换」「多选」）才下的结论。

## 6. 补充建议

| 优先级 | 做什么 | 为什么排这里 | 动哪里 | 怎么验 |
| --- | --- | --- | --- | --- |
| P0 | 库页失败加「重试」 | 现在失败只能退出重进，网页端早就有 | `LibraryPage` 的通知条加一个 `ActionButton`，接 `ReloadAsync` | 假传输 500 → 点重试 → 请求重发；库页探针加一条 |
| P1 | 菜单加「从这里开始播放」 | 「第 20 集往后连看」是看剧的高频动作；需要按当前排序取清单，但不用改播放器 | 用现有的 `PlayableItemsAsync` + 当前排序，从选中项截断 | 单测截断规则（跨分区、随机、筛选后） |
| P1 | 条目「媒体信息」 | 复用现成的 `MediaInfoDialog`，只补数据来源 | 按条目取 `/Items/{id}/PlaybackInfo`，菜单加一条 | 单测取数失败时不显示该条 |
| P1 | 菜单加「取消识别」 | 有「识别」没有撤销，识别错了只能自己再刮一次 | `ItemMenu` 在「识别」旁边加一条（服务器 ≥ 4.8.0.30 才显示），走 `resetmetadata` | 单测版本门槛；真实服务器只读核对接口 |
| P2 | 播放队列 | 三家网页端都有，我们一点没有；做完能一次补上 4 个入口 | 新增队列模型（Core 纯函数 + 播放器侧消费），设置里给开关 | 队列单测 + 播放器探针；三服务器的进度上报要分开验 |
| P3 | 多选批量 | 收益大但动的地方多（卡片、选中条、批量确认） | `PosterCard` 加复选框与选中态，`LibraryPage` 加选中条，批量走现有 `ItemCommands` | 选中条探针 + 批量写服务器的隔离验证 |
| P4 | 播放列表 | 依赖服务器端列表接口，且 Emby/Jellyfin/飞牛三套不一样 | 先只做 Jellyfin（有 `btnNewItem` 与 `addtoplaylist` 的现成接口） | 真实服务器只读 + 假传输 |
| 可选 | 菜单加「从开头播放」（D 类） | 网页端库页卡片并没有这一条，是我们自己的取舍 | `ItemMenu` 加命令，播放起点写 0 | 单测「有进度时多一条」；离线探针断言起点 |
| 暂缓 | 转换（A6） | 要轮询服务器任务、报进度，桌面端用的人少 | — | — |
| 不做 | 分享、录制、复制流地址、改库类型、播放列表排序 | 桌面端收益低，或多个依赖服务器开关，容易变成常年灰着的键 | — | — |

另外一条**复核项**（不是新功能）：B4 提到的读数。剧集库这类上百项的大库里，网页端一页 100 项、读数写「142 的 1-100」，翻页后变「142 的 101-142」；我们一直写「142 的 1-N」（N 是已加载数），且永远从 1 起算。滚动加载本身没问题，但**读数该不该跟着滚动区间变**要定一个说法：要么改成只报总数（「共 142 项」那种），要么跟着已加载区间走。现在这种写法在小库上碰巧对，大库上会误导。

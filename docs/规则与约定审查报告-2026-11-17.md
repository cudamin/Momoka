# Momoka 规则文件与约定审查报告

- 审查日期：2026-11-17
- 审查范围：项目常设规则、开发命令、交付台账、项目技能及相关脚本与源码实现
- 审查方式：只读对照，不修改产品代码，不运行构建、产品测试、探针、发布或真实服务器验证

## 一、总体评价

规则体系的方向正确：以 `CLAUDE.md` 为唯一政策源，配合四道闸门、真实服务器授权、红项不销账和交付台账，已经具备较强的安全与证据意识。

当前主要问题不是规则数量不足，而是：

1. 同一规则被多处摘要后发生漂移；
2. 现行命令与历史记录混排，部分命令不能直接照做；
3. 自动检查主要验证短语存在，没有覆盖跨文件语义、链接和完整执行路径。

综合评价：**框架完整性较好，但一致性和可执行性尚不足。** 应先修复高风险漂移，再统一命令入口和文档所有权，而不是继续增加重复规则。

## 二、优先级定义

- **P0：**涉及凭据安全、数据丢失或错误交付，应优先处理。
- **P1：**会直接导致错误操作、验证漏项或规则冲突。
- **P2：**主要影响维护性、可发现性和长期一致性。

## 三、P0 问题

### 1. Plex 播放认证说明与现行安全实现相反

**位置**

- [momoka-plex-api/SKILL.md:44](../.claude/skills/momoka-plex-api/SKILL.md#L44)
- [http-and-auth.md:15](../.claude/skills/momoka-plex-api/references/http-and-auth.md#L15)
- [EmbyUrl.cs:26](../src/Momoka.Core/Emby/EmbyUrl.cs#L26)

**问题**

上述位置仍描述为上游令牌直接成为 mpv 的 `--http-header-fields`。但当前实现是：

- [PlaybackHttpTransport.cs:63](../src/Momoka.Core/Playback/PlaybackHttpTransport.cs#L63) 将媒体地址映射到随机端口 loopback，并清空 native `HttpHeaders`；
- [momoka-playback/SKILL.md:24](../.claude/skills/momoka-playback/SKILL.md#L24) 已记录正确的匿名 loopback 规则。

**影响**

这不是发现当前正在泄漏凭据，而是旧文档可能诱导后续修改绕过 .NET 中转层，把令牌重新交给 native 进程、命令行或日志。

**修改建议**

统一改为：上游认证头仅由 `PlaybackHttpTransport` 保存和附加；libmpv/mpv.exe 只接收匿名随机端口 loopback URL，native headers 与 proxy 均为空。

同时修正 `EmbyUrl.cs` 旧注释。详细机制只保留一份，其他技能链接到该说明，避免再次漂移。

### 2. 分支清理规则丢失了防误删前提

**位置**

- 完整安全条件：[CLAUDE.md:135](../CLAUDE.md#L135)
- [momoka-verification/SKILL.md:24](../.claude/skills/momoka-verification/SKILL.md#L24)
- [待交付批次.md:3](待交付批次.md#L3) 及同文件第 14 行

**问题**

主规则要求确认内容全部进入 `master`、工作树干净、没有未保留改动或提交、不是其他聊天正在开发的树；技能和台账却简化为合并后自动删除快捷方式、分支和 worktree。

**影响**

单独阅读技能或台账，可能删除尚未真正进入主树的提交、未保留改动，或其他聊天正在使用的工作树。

**修改建议**

技能和台账必须同时保留以下条件：

- 以内容确认全部进入 `master`，不只看分支指针；
- 工作树干净，没有未保留改动或提交；
- 不是其他聊天正在使用的树；
- 条件未确认时只登记待清理，不执行删除。

将上述条件加入 [check-main-tree-policy.py:57](../tools/check-main-tree-policy.py#L57) 的技能和台账必检项及负例。

### 3. “完整测试通过”没有唯一、可全绿的执行定义

**位置**

- [开发与验证.md:1259](开发与验证.md#L1259)：闸门 2 标准命令只运行 `Momoka.Tests`；
- [开发与验证.md:1188](开发与验证.md#L1188)：`quality.ps1 -Tests` 执行 `run-regressions.ps1 -All`；
- [run-regressions.ps1:183](../tools/run-regressions.ps1#L183)：external 专项固定记为 skipped；
- [run-regressions.ps1:209](../tools/run-regressions.ps1#L209) 及第 232 行：skipped 最终导致 incomplete 和非零退出；
- [README.Regressions.md:25](../tools/README.Regressions.md#L25)：明确说明这一行为；
- [待交付批次.md:22](待交付批次.md#L22)：实际记录为 82 套中 81 套通过，外部 DOM 未运行。

**影响**

“闸门 2 已跑”可能分别表示只跑主测试、跑了托管专项但外部 DOM 跳过，或所有测试真正执行并通过。这三种结果无法从同一表述中区分，而且当前 `-All` 自身不能给出全绿汇总。

**修改建议**

建立明确的测试矩阵：

| 层级 | 内容 | 通过条件 |
| --- | --- | --- |
| 默认闸门 2 | `Momoka.Tests` | 全部通过，无 skip |
| 托管专项 | 所有可离线运行的登记项目 | 全部通过，无 skip |
| 外部专项 | DOM、Node、Playwright 等 | 必须实际运行并纳入汇总 |
| UI/播放检查 | 按改动范围选择 | 失败或必需项未跑均不能记全绿 |

至少提供一条能真正得到全绿结果的完整路径。外部结果需要进入同一份汇总，不能只保留“另见某目录”。

## 四、P1 问题

### 4. 闸门 3 标准命令漏掉 `-Shortcut`

**位置**

- [开发与验证.md:1404](开发与验证.md#L1404)
- [待交付批次.md:254](待交付批次.md#L254)
- [publish.ps1:239](../tools/publish.ps1#L239)
- 实际正确用法：[待交付批次.md:75](待交付批次.md#L75)

**问题与影响**

两处标准命令都只有 `-NoArchive`，但发布脚本只有显式传入 `-Shortcut` 才刷新快捷方式。严格照标准命令操作，会发布文件但不刷新快捷方式，却仍可能被认为完成闸门 3。

**修改建议**

标准命令统一为：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish.ps1 -NoArchive -Shortcut
```

同时明确主树、分支各自的 `.lnk` 名称及目标、`WorkingDirectory` 回读检查。`build.cmd` 若继续只发布，应明确标为“不刷新快捷方式”。

### 5. `quality.ps1` 与四道闸门的归属不够明确

**位置**

- [CLAUDE.md:79](../CLAUDE.md#L79)
- [开发与验证.md:1188](开发与验证.md#L1188)

**问题与影响**

`quality.ps1` 被称为统一入口，包含构建、空白、脚本、架构、重复率和 diff；闸门 1 的标准步骤却又单独列构建和格式检查。操作者可能只完成后两项，就误以为架构、重复率等检查也已覆盖。

**修改建议**

二选一：

- 将 `quality.ps1` 设为闸门 1 的唯一规范命令；或
- 明确哪些是闸门 1 必跑项、哪些是独立附加检查及其触发条件。

`-SkipBuild`、`-SkipDuplication` 等结果不得描述成完整闸门 1 通过。

## 六、建议修复顺序

1. 修正播放认证、分支删除前提、完整测试定义三项 P0；
2. 统一闸门命令、快捷方式参数和触发条件；

5. 最后再处理入口和路由等可发现性问题。

## 七、审查边界

本次原审查为只读操作：

- 未修改产品代码、规则、脚本或配置；
- 未运行构建、产品测试、探针、发布或 DOM 专项；
- 已运行 `py tools/check-main-tree-policy.py --self-test`，结果为通过：4 份文档、75 个负例被拒绝；
- 已进行只读本地链接扫描，发现 22 处失效引用、对应 8 个缺失目标；
- 未验证 ignored 旧技能是否会被宿主自动加载；
- 未读取真实凭据，未操作真实服务器。

政策自检通过只说明现有短语与负例检查通过，不能替代跨文件语义、链接有效性和命令可执行性审查。

# 分支清点与合并方案（2026-10-26）

本文是对本地 51 个分支、25 棵工作树的**只读**审查结果。审查过程没有修改、合并或删除任何分支、工作树与文件；文中所有判断都可用第 2 节的命令复现。

## 一、结论摘要

1. **主要问题不是"分支没清"，而是主干和一条审查修复线从 2026-10-21 起分叉后再没合过。** 主干之后走了 87 个提交（0.1.9、弹弹play、AniBT、MoviePilot、飞牛），审查线走了 105 个提交、549 个文件、10.9 万行。
2. **审查线是成品，不是半成品。** 它自己完成了最终验收（39 个项目零警告、Core 2885 项测试全过、自检 186 项零失败），验收记录在 `dddec63`；那条记录同时写明"不改 master、不 push"，所以它一直没回家。
3. **16 个 `codex/r0xx-*` 分支是这条审查线里的早期尝试**，已被主线同名修复取代。删它们不会丢内容，但**必须先确认审查线合入**。
4. **三条功能线各有独立实现，且都未定稿**：订阅设置、字幕翻译 Core、补帧。另有一条集成分支把三者与审查线合到一起，但 0.1.9 状态文档把字幕翻译和补帧标为 WIP。
5. 17 个分支的内容已经在主干里，可以安全删除；另外还有几处未提交的活（最多的一棵工作树有 337 个未提交文件）不能随树一起删。

## 二、审查方法与复现命令

| 判定 | 命令 | 用途 |
| --- | --- | --- |
| 是否已合入 | `git branch --merged master` / `--no-merged` | 分出已合入与未合入 |
| 内容是否等价 | `git cherry master <分支>` | `-` 表示补丁等价于主干已有提交 |
| 合并后会带来什么 | `git merge-tree --write-tree master <分支>`，再与 `master^{tree}` 比对 | 不落地地算出合并结果与冲突文件 |
| 合并成本 | `git diff --name-only master <合并树>`，滤掉 `PROGRESS.md` 与 `docs/` | 看真正会变的代码与资源文件 |
| 分支间包含关系 | `git branch --contains <提交>` | 找出叠罗汉的上下层 |
| 被取代核对 | `git show --name-only <提交>` + `git diff <分支> <主线> -- <文件>` | 比对同题修复的文件面与内容 |

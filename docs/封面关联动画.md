# 封面进入详情页的关联动画

2026-11-13 用户要求：点击封面进入详情时，封面保持可见并移动到详情左上角。实现沿用 WinUI Gallery 的图片关联动画；不新增依赖或手写移动轨迹。

## 源码依据

固定 Gallery 提交 `6de91feccadfbb0a796b71caedead5a2284f730e`：

- [ItemsRepeaterCollectionPage.xaml.cs](https://github.com/microsoft/WinUI-Gallery/blob/6de91feccadfbb0a796b71caedead5a2284f730e/WinUIGallery/SampleSupport/SamplePages/ItemsRepeaterCollectionPage.xaml.cs) 的 `NavigateToItem` 从模板取得实际 Image，先 `PrepareToAnimate`，随后 `Frame.Navigate` 搭配 `SuppressNavigationTransitionInfo`。
- [DetailedInfoPage.xaml](https://github.com/microsoft/WinUI-Gallery/blob/6de91feccadfbb0a796b71caedead5a2284f730e/WinUIGallery/SampleSupport/SamplePages/DetailedInfoPage.xaml) 的图片位于详情第一列上方；[code-behind](https://github.com/microsoft/WinUI-Gallery/blob/6de91feccadfbb0a796b71caedead5a2284f730e/WinUIGallery/SampleSupport/SamplePages/DetailedInfoPage.xaml.cs) 先填内容，再调用图片的 `TryStart`。
- Gallery 前进保留默认 Gravity，返回使用 Direct。沿用其调用顺序；源模板查找改用 Momoka 已有 `ConnectedPoster`，目标布局沿用当前详情页，保留本项目账号、图片版本、Frame、取消与动画偏好边界。
- [Microsoft Learn 动效原则](https://learn.microsoft.com/en-us/windows/apps/design/motion/)与[关联动画指南](https://learn.microsoft.com/en-us/windows/apps/design/motion/connected-animation)要求位置／尺寸变化保持连接，准备与启动之间避免网络请求；可先用低清图再替换高清图。

Gallery 样例图片来自本地资源；Momoka 的必要适配是在 Prepare 保存已显示的位图，平台冻结前保持来源 Source，目标已有条目与布局后立即启动。若目标高清图已经就绪则保留它；关联封面的高清替换在本次停留不再从透明淡入，下一次页面停留恢复普通图片到达动效。

## 行为与范围

首页、媒体库封面和预览“详情”入口，以及详情页剧季／更多类似封面均接入。支持同 Primary 图片的电影、剧集、季；单集详情使用剧封面，不能把单集剧照错误关联到剧封面。音乐、不同图、缺图、动画关闭、窄窗隐藏封面、旧账号和容器换项仍普通导航。

代码只保留现有原生关联动画路径。来源位图保留在完成、取消或超时时释放；详情继续深入时旧页面不能取消刚为新封面准备的票据。目标未 Loaded 时不在 Frame 的创建事务里触发普通回退。

## 点击封面后起跑延迟（2026-11-15）

用户：「点击封面后会卡一下才会触发动画，请修复」。原实现在 `TryStart` 前要求目标页 `Loaded`
（`Ticket.TryStart` 第一句），而详情页的第一次布局落在 `Loaded` 之前：Platform 侧
`PrepareToAnimate` 到 `TryStart` 之间源海报保持冻结，用户在点击后看到的是约两百毫秒的静止，
之后补间才开始（匿名探针 2026-11-15 的回执 `PrepareToStartMs` 冷启 1521ms、暖态 226～260ms）。

现在按 Gallery 的顺序抢跑：`Attach` 里先把 `Frame.ActualWidth` 交给视图模型（`SeedConnectedLayoutWidth`，
封面那一格的显隐与尺寸都问 `PageWidth`），强制一次布局（`ForceConnectedLayout`），随后 `TryStartEarly`
在目标图已排过版时直接 `TryStart`，不再等 `Loaded`。抢跑只在身份、图版本、源卡可见性都对得上时发出；
任何一条不满足都只是这一趟不抢，判定与回退仍由 `Loaded`／`LayoutUpdated` 那条原路负责（新页创建期间
不能把票据判死，见 2026-11-13 的 Frame 创建打断回归）。`LayoutUpdated` 在页面尚未 `Loaded` 时也先走
抢跑，因此即使导航事务里的强制布局排不出来，动画仍能在第一次布局落定时起跑。

`VisibleImage` 拆成「`Loaded` + `ArrangedImage`」两问：抢跑那一路只问「排过版、画得出画面、在视口里」，
真实落点由强制布局给出，不会把 0×0 交给平台。测试新增「已排过版时在新页 Loaded 前立即起跑」与
「第一次布局落定即可起跑」两项，原有「新页未 Loaded 时图版本更正不打断 Frame 创建」的边界保持不变。

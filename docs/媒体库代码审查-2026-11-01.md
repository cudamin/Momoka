# 媒体库功能代码审查（2026-11-01）

审查范围：媒体库页（`LibraryPage` + `LibraryViewModel`）、条目「更多」菜单（`ItemMenu` + `ItemCommands`）、以及四家服务器的浏览适配器（Emby / Jellyfin / 飞牛影视 / Plex）。

审查问题两条：**功能是否齐全**、**有没有加进来却用不了的入口**。

判据不是印象，是三样东西对齐：

1. `CLAUDE.md`「功能可用性与显隐」——无法使用或在当前配置下不会生效的功能必须收起，不许置灰、不许补说明代替隐藏。
2. 三家网页端留档（`work/媒体库网页端源码`，Emby 4.10.1.0 / Jellyfin 10.10.7 / 飞牛 0.9.8）。
3. 适配器自己声明的能力边界——`NotSupportedException` 抛在哪儿、哪个查询参数被谁读、哪个被谁丢掉。

---

## 一、结论

**齐全度：核心浏览层是齐的，能力层缺三样，另有一格是占位。**

工具条（总数 / 播放 / 随机播放 / 排序 / 筛选 / 设置 / 布局 / 更多）、分区签、字母条、筛选项筹码、空态、卡片悬浮按钮、条目菜单二十来条——按服务器该有的都有，该收的也收了。真正缺的是：库页**加载失败没有「重试」**、卡片菜单**没有「从这里开始播放」**、**没有多选批量**；电影库的「推荐」分区是**整库列表的占位**，不是推荐。

**上一份核对报告（`媒体库网页端按钮核对-2026-11-01.md`）有两条要更正**，这次读实现才看清：

| 上次写法 | 实际 |
| --- | --- |
| 「取消识别」缺失 | **已有**。它在「识别」对话框里（`IdentifyDialog.xaml` 的「移除识别」，二段确认），Emby 可用；Jellyfin 因为客户端没实现重置接口才不显示 |
| 条目「媒体信息」缺失 | **已有**。详情页的「媒体信息」表就是它（文件名、格式、码率、音轨…），只是没做成库卡片菜单里的一条 |

**无法使用的功能：找到 4 处**，其中 1 处点进去必失败（飞牛按类型浏览），2 处是「摆着但不起作用/名不符实」，1 处是配置里存在、界面上不可达。

## 二、逐条发现

### F1（阻断）飞牛影视：详情页的「类型」是可点链接，点进去必然加载失败

- 详情页那一行类型的每一个词都是超链接，点击走 `DetailViewModel.OpenGenre` → 外壳开一格「这个类型下的全部影片和剧集」。
- 判据只看了一件事：**不是 Plex 就能点**。`DetailViewModel.cs:1239`：`CanOpenGenre => Attached && _scope?.Connection.IsPlex == false`。飞牛不在排除名单里，于是链接着色、可点。
- 但飞牛的查询构造对「题材」是明确拒收的：`FnNasMediaAdapter.Models.cs:13-15` 只要 `Genre` 非空就抛 `NotSupportedException("飞牛影视尚不支持此浏览条件")`；`tests/Momoka.Tests/FnNasMediaTests.cs:429` 还专门钉了这条，注释写的是「题材取值形状未核对，不能把猜的数组发给服务器换 -4」。
- 类型页的查询又确实带着 `Genre`：`LibraryViewModel.cs:2691-2700` 构造 `ItemQuery { Genre = genre, Recursive = true, ... }`，且没有父级。
- 结果：飞牛详情页点类型 → 请求抛异常 → 网格空白 + 顶部「读取「X」失败：飞牛影视尚不支持此浏览条件」。

**为什么会漏**：把「跨库题材查询」当成 Plex 独有的缺口（注释原话「当前客户端未实现 Plex 跨库题材查询」），而飞牛的适配器同样没有这条路，只是拒绝的位置更深一层。Plex 被想到，飞牛被漏掉。

**修法（二选一）**：
- 小：`CanOpenGenre` 把飞牛一起排除（`IsPlex == false && IsFnNas == false`），那一行退回普通文字 —— 符合「无法使用的入口收起」的规矩；
- 大：飞牛的题材本来就在它自己的标签体系里（`genres` 是数字 id，`/tag/list` 会给候选），走筛选面板的 `tags.genres` 是现成的；要真做，得把类型页翻译成一次 `tags` 过滤，属于新功能。

**证据强度**：代码路径完整、有单测钉住适配器行为；没有在真实飞牛服务器上点过（本轮不登录、不写服务器）。

---

### F2（中）Plex 库页「设置」里的「将项目分组到合集中」是空开关

- Plex 媒体库的工具条上有齿轮（`LibraryViewModel.cs:644`：`(!IsFnNas && !IsJellyfin)` 都放行，Plex 在其中），点开是 `LibrarySettingsPanel` 的四组：视图 / 图像大小 / 将项目分组到合集中 / 显示字段。
- 「分组」这一项的去向是 `LibraryBrowse.cs:156-157` 写进 `ItemQuery.GroupItemsIntoCollections`，再由 `ItemQuery` 拼成 `GroupItemsIntoCollections=true/false`。
- Plex 的查询完全不读这个字段：`PlexMediaAdapter.Models.cs:20-32` 只翻 `SortBy`、`IncludeItemTypes`、`IsPlayed` 三样；`PlexClient` 与适配器里没有任何 collection 分组的实现（全仓 `grep -i collection` 在 Plex 目录只命中「合集条目类型」的映射）。
- 于是这个开关拨了只会让网格重查一次，画出来的东西一模一样。用户看不出它没生效，只会以为「Plex 本来就不分组」。

**修法**：面板按服务器裁剪 —— Plex 下把 `GroupSection` 收起（Jellyfin 那颗齿轮本来就不出现，飞牛另有一套「布局」）。同一条规矩在 `HasToolbar`、`SettingsVisibility` 里已经用过很多次，这里只是漏了一份「哪些设置这一家有」。

**旁证**：`EmbyClient.Protocol.cs:18-20` 对 Jellyfin 是显式删掉这个参数的，注释写着「Jellyfin 的 /Items 没有这个参数」—— 说明作者知道这个开关不是人人都有，只是没给 Plex 补同样的处理。

---

### F3（中）Emby 电影库的「推荐」分区名不符实：看到的是整库列表

- 电影库分区签里第二个就是「推荐」（`LibraryBrowse.cs:56-59`）。
- 「推荐页」的成立条件是 `LibraryRecommended.Rows(...)` 非空（`LibraryViewModel.cs:808-809`），而它对 Emby 电影库返回空表（`LibraryRecommended.cs:59-81`：只有 Jellyfin 电影、两家电视剧各一套）。注释也承认「电影库没有这几排（网页端电影库的推荐是另一组行，本轮没做）」。
- 不成立就走普通网格：`LibraryBrowse.cs:172` 对推荐分区把排序写成空串（`SortBy = ""`），类型退回整库（`Movie, Video`），工具栏又被 `HasToolbar` 收掉（`LibraryViewModel.cs:638-640`）。
- 用户看到的是：**所有电影、服务器默认顺序、没有总数/排序/筛选**。网页端这一页是三排货架「继续观看 / 最新电影 / 最新影片」（留档 `work/媒体库网页端源码/pages/emby/电影.html` 里三处 `sectionTitle` 就是这三句）。

**为什么算缺陷**：这不是「少做了一点」，是把一个明确叫「推荐」的入口做成了「全部」。按项目自己的规矩，做不了就该收起这个分区签，或者退回上一版真能用的东西。

**修法**：二选一 —— 短期把 Emby 电影库的「推荐」分区签去掉；或者补 `Users/{id}/Suggestions` / `Movies/Recommendations` 那几排（Jellyfin 电影那套已经做过，可以复用 `CardShelf` 与 `LibraryRecommended.Query` 的形状）。

**证据强度**：代码 + 网页端留档双向对上；没有实机对比截图。

---

### F4（中）库页加载失败没有「重试」，只能退出重进

- 失败的反馈只有顶部一条 `InfoBar`（`LibraryPage.xaml:821-829`），它可关闭、没有动作按钮；总数读数变成「加载失败」（`LibraryViewModel.cs:694-698`）。
- 页面上唯一的 `Reload()` 入口绑在**预告页**那颗「重新加载」上（`LibraryPage.xaml.cs:850`），主网格没有。
- 也就是说：服务器超时一次、或如上一条那种「适配器拒收」，用户只能靠返回再进（或者切一次分区）来重来。网页端两颗 `btnRetryData` 都给了。

**修法**：`InfoBar` 加 `ActionButton`（文案「重试」）接 `ReloadAsync`，与预告页那颗走同一条路。改动很小，是这次唯一「纯增量」的补齐项。

---

### F5（轻）飞牛媒体库的「收藏」分区存在但不可达

- 分区表给飞牛留了 `Items` 与 `Favorites` 两项（`LibraryBrowse.cs:79`）。
- 分区签对飞牛整体收起（`LibraryViewModel.cs:630`：`Show(!IsFnNas && ...)`），而库根进来时分区恒为 `Items`，没有第二条路把 `Section` 设成 `Favorites`。
- 收藏本身在别处可达（标题栏收藏页、详情页与卡片菜单），所以这不是功能缺失，是**一份没有出口的配置**。留着它只会让下一个人以为飞牛有分区收藏页。

**修法**：把飞牛那一行改成只留 `Items`，或者在飞牛的库页真给一个「收藏」入口（官网页端没有，故推荐前者）。

### 附带观察（不算缺陷，但要说明）

- **Plex 的「显示字段」有一半恒为空**：`PlexMediaAdapter.Models.cs:81-134` 的 `Item()` 只映射片名、简介、年份、评分、类型、工作室、标签、用户状态，不映射 `People`（导演/编剧）、路径等。打开「导演」这一列，Plex 上是空的。属于数据源限制，可接受，但用户会以为坏了。
- **Plex 的排序只有 5 档**（名称/加入日期/首映日期/评分/随机，`PlexMediaAdapter.Models.cs:13`）。菜单已按 `SupportsSort` 裁过，不是缺陷，只是与 Emby 的十九项差距要注意解释。
- **卡片悬浮按钮的判据是按条目类型，不是按页面**（`CardItem.cs:522-543`）—— 媒体库卡、演员卡不会出现「已观看/收藏」，这一层是对的。

## 四、建议与优先级

| 优先级 | 事项 | 量级 | 验收方式 |
| --- | --- | --- | --- |
| P0 | F1 飞牛类型行改成不可点（或直接隐藏） | 一行判断 | 单测：飞牛 scope 下 `CanOpenGenre` 为假；探针看类型行画成纯文字 |
| P0 | F4 失败提示条加「重试」 | 一个按钮 + 一条命令 | 假传输 500 → 点重试 → 请求重发；库页探针加一条 |
| P1 | F2 Plex 收掉「分组」这一行 | 面板按服务器裁剪 | 面板探针：Plex 下 `GroupSection` 收起；Emby 下仍在 |
| P1 | F3 电影「推荐」分区：先收起分区签，或补 Suggestions 三排 | 收起=一行；补齐=一轮 | 收起：分区签不含「推荐」；补齐：三排货架断言 |
| P2 | 「从这里开始播放」「多选批量」 | 中 / 大 | 见上一份报告的分级 |

**先做 P0 两条**：它们一个是「点了一定失败」，一个是「失败了没法重来」，都属于「用户当场就会撞上」的级别，且改动面都只有一两处。

## 五、审查边界（如实说）

- **没有构建、没有跑测试、没有跑探针、没有发布**。这次是读代码，结论全部来自源码与留档，不是运行证据。
- **没有连真实服务器**：没有登录、没有播放、没有写服务器；飞牛那条的「点进去会失败」是代码路径推断（外加单测钉住的适配器行为），不是实机截图。按项目规矩，飞牛与 Plex 本就标着「真实服务器未核对」，这条也要实机确认一次。
- **只看了媒体库这条路**：首页货架、详情页、播放器、MoviePilot/AniBT 面板只在「与库页共用同一份判断」时才看（例如 `ItemMenu`、`CardItem`）。
- 没做性能、可访问性、本地化与视觉密度审查；自动化句柄基线、字号颜色基线也没复核。

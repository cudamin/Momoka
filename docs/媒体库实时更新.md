# 媒体库实时更新

首页进入时为在线 Emby、Jellyfin、Plex 来源各建立一条 WebSocket，离页、退出账号时关闭。飞牛影视保留 HTTP 轮询。所有来源仍每 30 秒核对最新列表，推送只提前唤醒同一核对流程，前 24 项的 ID 或顺序变化后才重读首页货架和轮播。没有新增系统通知或全局常驻监听。

## Plex

连接服务器的 `/:/websockets/notifications`，保留反向代理前缀；`X-Plex-Token` 与 `X-Plex-Client-Identifier` 只在请求头，URL 无令牌。连接后被动接收，不发送订阅命令。

- `NotificationContainer.type=timeline` 的 `TimelineEntry` 数组：仅库 identifier `com.plexapp.plugins.library`、正数 `itemID/sectionID`、整数 state 0/5/9 唤醒核对。
- `type=status` 的 `StatusNotification` 数组：`notificationName=LIBRARY_UPDATE` 唤醒核对。
- 同时接受官方保留的旧 `_elementType=NotificationContainer`、`type`、`_children` 封装。
- 其他播放、进度、DVR 节目表和畸形消息不触发。state 5 是本地额外核对，用于元数据处理完成；它不是“确定新媒体已入库”的证明。

## Jellyfin

服务端发送 `{"MessageType":"ForceKeepAlive","Data":60}` 后，客户端立即发送不带 Data 的 `{"MessageType":"KeepAlive"}`，以后每半周期发送。WebSocket 帧级 Ping/Pong 不能替代这条会话心跳。本地接受 2..3600 的整数秒，保证间隔至少一秒；这是本地资源预算，不是上游声明的范围。

一个 socket 只有一个发送循环。更新周期只唤醒等待，不取消在途网络发送；离页、来源退出、socket 结束时才取消并等待循环。发送错误 Abort socket，让既有接收和重连流程接管。

## Emby 与飞牛边界

Emby 路径保留：官方 [JS](https://github.com/MediaBrowser/Emby.ApiClient.Javascript/blob/fdd0939ac596406ab92274f30fd83d226a677424/apiclient.js#L1101) 把 `/emby/socket` 替换为 `/embywebsocket`；官方 [C#](https://github.com/MediaBrowser/Emby.ApiClient/blob/b2e124f789b6f086b7b5b7e88e07c902e946f5b2/Emby.ApiClient/ApiWebSocket.cs#L328) 在 ApiUrl（带 /emby）后追加 /embywebsocket，和 Momoka 当前路径相同。该差异不能单独证明当前路径错误；真实服务器 header-only 握手仍待核对。

飞牛检查的是 2026-10-15 保存的官方 0.9.8 前端，共 65 个 JS、5,644,474 字节，依赖 chunk 闭合。原下载 URL 未保留，不能称为本次线上最新版本证据。SDK `14a77ac952fc83b785b65592c335e16d-BGXwY7Sz.js` 的 152 个路由未见入库推送；主包 `74c95604043427f0bee1d0e16bfa53af-DZn1lJtt.js` 的 TaskStoreProvider 每 3 秒读取 task.running，页面 `media:library:refreshed` 是本地 EventEmitter；仅发现的 WebSocket 属 flv 媒体二进制加载器。SDK SHA256 `e244e703491c58f2e354be13a2dc00a6354ad352bb6519e90d7e28a188d9f0a6`；主包 `92a8becea3c705a448301b49fe7368722a136368137cd541986f3c3ffc3a5527`。目前未取得可实施的飞牛原生入库推送协议，不能猜接口或改接 fnOS 系统通道。

## 验证边界

当前 Release Core/Tests 编译后运行 `realtime-handshake-fixture`，覆盖三产品头部握手、换令牌重连、Plex 实际 Watch 通知与离页、拒绝跳转，以及 Jellyfin 立即/周期/更新/重连心跳；阻塞发送替身验证更新周期不会取消在途写。`Momoka.ResourceBudgetTests` 的 websocket 与 compatibility 分组覆盖消息预算和既有握手回归。

只使用匿名回环网络、内存 REST 替身和隔离测试输出。它们不证明真实媒体服务器、共享账号权限、TLS、代理、WinUI 渲染或真实入库消息可用；实际运行结果记录在 PROGRESS.md。

## Plex

- `NotificationContainer.type=timeline` 的 `TimelineEntry` 数组：仅库 identifier `com.plexapp.plugins.library`、正数 `itemID/sectionID`、整数 state 0/5/9 唤醒核对。
- `type=status` 的 `StatusNotification` 数组：`notificationName=LIBRARY_UPDATE` 唤醒核对。
- 同时接受官方保留的旧 `_elementType=NotificationContainer`、`type`、`_children` 封装。
- 其他播放、进度、DVR 节目表和畸形消息不触发。state 5 对应元数据处理完成；本次进一步确认官方 Home reducer 也消费 metadataProcessed，使相应 hub 失效。它不是“确定新媒体已入库”的证明。

## Jellyfin

服务端发送 `{"MessageType":"ForceKeepAlive","Data":60}` 后，客户端立即发送不带 Data 的 `{"MessageType":"KeepAlive"}`，以后每半周期发送。WebSocket 帧级 Ping/Pong 不能替代这条会话心跳。本地接受 2..3600 的整数秒，保证间隔至少一秒；这是本地资源预算，不是上游声明的范围。

一个 socket 只有一个发送循环。更新周期只唤醒等待，不取消在途网络发送；离页、来源退出、socket 结束时才取消并等待循环。发送错误 Abort socket，让既有接收和重连流程接管。

- [Jellyfin SessionWebSocketListener.cs](https://github.com/jellyfin/jellyfin/blob/83d0d0e7f76e23e2e085c8ff67d28b772d35967d/Emby.Server.Implementations/Session/SessionWebSocketListener.cs)：固定提交，26 行超时 60 秒，221 行判失联，277 行发送 ForceKeepAlive。SHA256 `97794eac54f19c62b968714763036547f65458f5be3b99faefe189174172c520`。

## Emby / Jellyfin 官方首页

本次匿名重取实际网页关联资源 34 份，均与保存缓存 SHA256 一致。Emby 4.10.1.0 的 `sectionscontroller → itemscontainer → itemsrefresher` 只有服务端分区下发 `RefreshInterval` 才设置毫秒计时器。实际 GET `Users/{uid}/HomeSections?displayMode=mobile,desktop` 返回四个 `latestmedia` 均未设置周期，只有 `onnow=300000`（直播）。旧版客户端生成的最新媒体分区同样无周期。

Jellyfin 10.10.7（jellyfin-web `f4b8aa0ed4c5b571a3a6cc3bb027bb8ecebe5b68`）`recentlyAdded.ts` 不设置 `data-refreshinterval`；`emby-itemscontainer.js` 由关联的 `LibraryChanged` 新增/删除触发。另核最新 master `0e68daff9f24f255e77182a9d78acfd1cef735b5`，该结论相同。两家都无“WebSocket 重连成功就重查首页”的调用，所以没有新增这种兜底。官方远程事件分别合并 3 秒/10 秒，Momoka 保留现有单队列合并与列表指纹核对，不照搬 DOM 容器的取消旧请求策略；忙碌时保留待处理事件。

关键原字节：Emby itemsrefresher `39ec671b70b9d8d02fb7c103e709dc7d37ed7040d013842ce7390e03acb3edff`；实际 Jellyfin hometab `52991f0cc4659b48c3e55acbb50ef4b5003d23187719b851ee630ca1fb13d4e9`。完整调用条件、行号与清单在 `work/push-audit-20261110/emby-jellyfin/report.md` 与 `anonymous-source-receipts.json`。

## Emby 端点与飞牛任务

Emby 路径保留：官方 [JS](https://github.com/MediaBrowser/Emby.ApiClient.Javascript/blob/fdd0939ac596406ab92274f30fd83d226a677424/apiclient.js#L1101) 把 `/emby/socket` 替换为 `/embywebsocket`；官方 [C#](https://github.com/MediaBrowser/Emby.ApiClient/blob/b2e124f789b6f086b7b5b7e88e07c902e946f5b2/Emby.ApiClient/ApiWebSocket.cs#L328) 在 ApiUrl（带 /emby）后追加 /embywebsocket，和 Momoka 当前路径相同。该差异不能单独证明当前路径错误；真实服务器 header-only 握手仍待核对。

本次从已知实际飞牛服务匿名重新获取官方 0.9.8 网页（媒体服务 0.8.45），65 个 JS、5,644,474 字节、434 条依赖闭合；旧清单的全部 64 个 JS 哈希一致，另补 jassub 辅助脚本。SDK `14a77ac952fc83b785b65592c335e16d-BGXwY7Sz.js` 的 152 个路由没有媒体入库推送；唯一 WebSocket 构造属于 flv 二进制播放加载器。SDK SHA256 `e244e703491c58f2e354be13a2dc00a6354ad352bb6519e90d7e28a188d9f0a6`，主业务包 `92a8becea3c705a448301b49fe7368722a136368137cd541986f3c3ffc3a5527`。

官方首页的实际更新机制：

- 普通账号不查询任务；管理员首次 GET `api/v1/task/running`，之后每次完成再等 3 秒查询，不重叠请求。
- 只取 `type=TaskItemScrap` 的去重 ancestor；旧集合中至少一个 ancestor 从新集合消失才触发。不按 status 过滤，任务新增或仅状态变化不触发。
- 完成后只重读 `mediadb/list` 和 `mediadb/sum`。已有正数货架不重读；sum 变 0 隐藏；新库或非正数变正数才首次读取该库媒体。`media:library:refreshed` 是手动库刷新成功时的页面本地事件，任务轮询不发该事件。
- Momoka 复用现有任务与目录协议，当前权限决定是否查询，读取失败保留上次成功任务基线，离页取消。官方 TaskStore 在多个路由存活；Momoka 只在使用结果的首页监控，不为未实现的全局任务面板常驻联网。
- 原生入库推送仍未找到；这次实现的是经源码确认的任务轮询。官方 task/running 免 authx，Momoka 现有传输额外带 authx 的调用本次实服已成功，不改动共有签名策略。

完整依赖清单和 14 个原始 hook 隔离运行场景在 `work/push-audit-20261110/fnnas/`。未把 fnOS 系统 WebSocket 当成影视入库协议。

## 验证边界

当前 Release Core/Tests 编译后运行 `realtime-handshake-fixture`，覆盖三产品头部握手、换令牌重连、Plex 实际 Watch 通知与离页、拒绝跳转，以及 Jellyfin 立即/周期/更新/重连心跳；阻塞发送替身验证更新周期不会取消在途写。`Momoka.ResourceBudgetTests` 的 websocket 与 compatibility 分组覆盖消息预算和既有握手回归。

2026-11-10 真实只读验证：Emby 4.10.1.0 与 Jellyfin 10.10.7 的当前头部握手均 101，连接观察 150 秒未被服务端断开；Jellyfin 收到 ForceKeepAlive 1 次、KeepAlive 5 次。三个已配置来源最新媒体读取成功；飞牛管理员 task/running 成功（当时 0 任务），目录/计数成功（3 库）。配置内容哈希未变，没有保存、登录回退、扫描、播放或媒体写入。Plex 无已配置实服，按用户选择只验协议。

用户明确本轮不安排真实入库，观察期没有 LibraryChanged，所以不宣称真实新媒体事件已送达；没有事件游标/断线补发保证，去掉通用轮询后断线期间可能要靠进入页面或手动刷新补读。匿名协议/实际 VM 测试不能证明 TLS、代理、WinUI 渲染或实服入库全链。最终结果记录在 PROGRESS.md。

# 媒体库入库推送

用户要求接入推送，让新入库尽快出现在现有首页。沿用首页进入时连接、离开时取消和每 30 秒 HTTP 核对的范围，不新增系统通知或后台常驻服务。

## 方案与取舍

采用服务器原生 WebSocket 加现有 HTTP 核对。Plex 原生通知接口有官方前端及 Tautulli 源码依据；Webhook 需要额外服务端配置、可达的客户端地址和监听服务，当前桌面客户端不采用。纯轮询继续作为兼容和断线兜底。

- Plex：连接 `/:/websockets/notifications`，保留部署前缀，令牌和设备标识仅在请求头。识别 `NotificationContainer` 中 timeline 的合法库条目 state 0/5/9，以及 status 的 `LIBRARY_UPDATE`。0/9 和 status 刷新有官方前端依据；5 提前核对是本地选择，用于处理创建后元数据完成。接受官方保留的旧 `_elementType/type/_children` 封装。消息仅唤醒现有核对，不直接合成或插入卡片。
- Jellyfin：收到 `ForceKeepAlive` 后立即发送 `{"MessageType":"KeepAlive"}`，此后每半周期发送。每个 socket 只拥有一个发送循环，重发指令替换旧周期；离页、退出、重连及发送失败均终止旧循环。官方 Data=60；本地只接受 2..3600 的整数秒，拒绝畸形输入和亚秒发送频率。
- Emby：保留现有路径。官方 JS 使用 `/embywebsocket`，官方 C# 使用 `/emby/embywebsocket`，无真实服务器证据前不将差异认定为缺陷。
- 飞牛：已保存的官方 0.9.8 前端使用 HTTP 任务轮询和本地事件总线；未取得可实施的原生入库推送协议，保持当前轮询。

复用连接取消、最新来源令牌、拒绝重定向、指数退避和 1 MiB 消息预算，不加入依赖。保留已有前 24 项 ID/顺序变化判据；推送不保证同 ID 元数据更新被刷新。

## 验证

先新增失败测试，再实现。使用匿名回环服务器验证 Plex 请求头、消息过滤、真实回调、换令牌重连、离页取消、拒绝跳转；Jellyfin 验证立即与周期心跳、更新周期、重连后旧发送任务退出。回归 Emby/Jellyfin 既有握手与消息预算，并运行当前 Release 主测试。真实媒体服务器、共享账号权限、TLS/代理和真实入库事件不在离线证据内。

方案中的实现选择由助手按现有项目架构决定。主树存在其他会话未提交工作，开发留在本聊天独立树，整合与发布必须核对所有者及最终代码。

# 媒体库更新与官方客户端对齐

用户要求继续查飞牛推送、核实四个后端的连接与网页轮询，并指定「官方客户端怎么做的你就这么改」。验证范围已明确：Emby、Jellyfin、飞牛使用已保存来源只读检查；Plex 仅协议测试；本轮不安排真实入库。

## 方案与范围

删除 Momoka 首页每 30 秒拉取全部最新媒体的通用兜底。保留 Emby/Jellyfin/Plex 原生推送及连接重试；按官方事件驱动核对。读取期间收到的通知保留到可执行时，不能依赖下一个定时周期补救。首读、导航回来和手动刷新仍读取服务器。

飞牛当前官方 0.9.8 页面没有可证的媒体入库推送。按官方首页实现，仅管理员每 3 秒 GET task/running；TaskItemScrap 的 ancestor 从旧集合消失时读取 mediadb/list 与 mediadb/sum，更新库目录和计数。普通账号不轮询、不把任务变化伪装成原生推送，也不无条件刷新 item/list 货架。

Plex 官方全局首页无常驻轮询；它的媒体库推荐货架页在扫描中每 10 秒更新 hubs。Momoka 对应页面是否存在须从当前能力入口核实；无对应页面时不新增该页面，不把条件循环移植到首页。

## 取舍

不保留任意后端通用轮询：用户指定按官方实现。不猜飞牛 WebSocket，也不借 fnOS 系统通道。真实连接成功与库事件送达分别报告；没有本轮真实入库，因此不宣称完整入库链已实证。

## 验证

真实只读连接观察已经完成 150 秒：Emby/Jellyfin 101，Jellyfin ForceKeepAlive 一次、KeepAlive 五次，三个来源最新媒体读取成功，配置哈希不变。产品变更还需当前 Release Core/Tests/Shell 编译、消息协议测试、实际 HomeViewModel 生命周期回归、飞牛任务状态与权限回归、主树整合重验及发布。

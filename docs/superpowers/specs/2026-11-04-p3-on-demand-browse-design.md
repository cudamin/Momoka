# P3：长剧与深返回按需工作

执行依据：用户在完成 P2 后要求“p3”；范围沿用《页面切换与封面响应延迟审查及优化方案》的 P3。下面是源码核对后的实现选择，不是新增产品需求。

## 长剧

保留全剧 DTO、播出顺序、最早未看集、特别篇、当前季定位和播放上下文。将详情集卡改为按索引访问时创建，集合 Count 与全局索引保持完整；普通货架保持原行为。清理、删除、查询已创建卡不得顺手实例化全部卡。集合必须提供 WinUI 可索引的非泛型 IList 和变化通知；只提供 IEnumerable 会触发平台遍历复制。

后台只处理独占的 DTO 列表排序；发布前仍核对取消、来源和页面代次。UI 仅发布列表状态和实际被布局访问的卡。全量 HTTP 暂保留，因为选择最早未看和全剧顺序需要完整业务索引；不宣称节省全剧网络请求。

比较：从头分批创建仍会创建所有卡，深处当前集须等前面完成；局部窗口重新编号会改变季跳转和左右翻页。选择保留全局索引的按需卡集合。

## 深返回

单来源普通稳定查询保存最多 400 项的锚点附近窗口，附服务端起点和滚动锚点。返回先显示窗口，后续向前/向后按页补读；不从第一页串行重放历史。分页、计数、字母跳转、播放全部、删除回填、后台核对都必须理解窗口起点。来源代次、查询键、10 分钟 TTL 和 LRU 容量沿用。

排除聚合、Resume、NextUp、搜索、收藏、推荐、Upcoming、Random；它们保留现有路径。Emby/Jellyfin 普通查询透传 offset；飞牛普通 item/list 做页号映射；Plex 普通库根使用容器分页头。按适用能力分开验证，不把假传输或 Emby 实测算成全部服务器实测。

比较：提高快照上限只推迟问题；大请求或后台重放历史仍做无用工作。选择有限窗口和双向增量读取，保持顶部可继续到第一页。

## 验收

- 2000 集跳到中后段不创建前面所有 CardItem；季跳、边界翻页、删除、取消和重复进入正确，全剧播放索引完整。
- 2000 项库在 1500 附近返回，缓存不超过 400 项；首轮请求从窗口起点开始；可继续向上/下、重新排序、刷新、字母跳转与构造完整播放清单。
- 原集合引用稳定；旧账号/取消结果不回填；后台失败保留可读状态并有反馈。
- 新鲜 Release 测试、实际 Frame 探针、宽窄实屏及最终主树发布。运行检查串行，不停止他人进程；没有真实播放/服务器写入。
- 记录对象数、请求起点/次数和实际时延，环境混杂时不作性能因果结论。

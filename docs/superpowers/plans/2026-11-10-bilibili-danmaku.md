# B 站登录与弹幕接入计划

> 使用 writing-plans、并行子代理与 test-driven-development 执行。沿用用户直接实施偏好。

**目标：** 在设置的弹幕分类登录 B 站，并在内置播放器自动匹配、加载 B 站弹幕；不确定时手动选择。

**设计：** 新增独立 Bilibili 来源，保持旧 Both 的两源语义。官方登录页由独立 WebView2 承载，候选 Cookie 通过固定官方 nav 接口验证后 DPAPI 保存；导出配置不含身份。使用源码核对过的 WBI 番剧/影视搜索、BV/av/ep/ss 详情和 cid XML 弹幕。复用现有弹幕结果模型与渲染图层，不新增 B 站发送能力。按用户追加要求自动匹配：只有完整候选里的唯一精确标题和明确一致集号才能加载；续季与特别篇沿用既有保护，不确定时手选。

**取舍：** 官方网页复用已有依赖和官网登录流程；自行实现二维码需要另行维护登录接口。XML 是公开客户端已采用的当前弹幕池，不承诺完整历史或高级脚本弹幕。

**约束：** .NET 10 / WinUI 3；不新增包；固定官方 HTTPS，请求拒绝重定向；不记录 Cookie 和原始响应；30 秒预算、32 MiB 响应及 40000 条弹幕上限；关闭/换源/换片拒绝迟到结果。真实登录、播放与发送不用于离线验证。

## 实施与验证

- [ ] Core 来源和设置：匿名测试验证旧枚举兼容、登录前后可用性、凭据保护、备份和恢复边界。
- [ ] BilibiliClient：假 HTTP 验证 WBI、内容编号解析、分集、XML、错误、取消、响应限长与关闭排空。
- [ ] 设置登录：官方 WebView2、账户/退出入口、保存失败回滚、关闭取消；运行核对显隐和宽窄布局。
- [ ] 播放接入：来源分派、搜索、加载和状态统计；原发送目标隔离、换源换片迟到数据拒绝。
- [ ] 终码编译和正式测试、相关边界测试、Shell 探针及实屏检查；独立审查后提交。
- [ ] 核对主树状态，整合、重验并发布；不上传远程。

## 审查重点

退出期间在途登录不得重新写回凭据；配置备份不得含密文或账号；官方顶级导航不允许相似域；cid 和其他来源 episodeId 重号不得混用；XML 非法/高级模式不得进入 ASS；关闭必须排空客户端活动操作。

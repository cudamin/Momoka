# 媒体库第三批实现计划

> 使用 subagent-driven-development 在隔离工作树实施，父会话整合并验证。

**目标：** 减少重复整理，完成路线图第三批的多选和飞牛移出/恢复配对入口。

**架构：** 沿用 LibraryPage 的 ItemsView 多选及各服务器自己的能力判断；批量执行放在服务，页面负责选择、确认和结果展示。飞牛用独立协议与管理入口。

**范围依据：** 用户指定的 2026-11-10 momoka-library-roadmap.md 第三批。直接实施正式功能；不增加 Demo 审批。仍遵守 CLAUDE.md 的真实写入和播放验证边界。

**取舍：** 采用现有媒体卡墙原生多选，保留海报/缩略图/列表/表格布局；聚合跨账号写入不开放。飞牛只补移出和恢复，Plex 先只复用已确证的已看/未看。

- [ ] Emby/Jellyfin 批处理规则和服务：逐项权限、捕获来源、成功/失败/取消分开，刷新失败不重复写入；离线 HTTP 回归。
- [ ] 飞牛官方前端证据、单条/版本移出与已移除文件恢复配对入口、权限和取消回归。
- [ ] Plex 官方单项证据与权限边界，已看/未看离线回归。
- [ ] LibraryPage 多选工具栏、原生选择、选择期间关闭播放/单项动作、取消/状态回馈；页面契约与原生宽窄布局探针。
- [ ] 整合、独立复核、最终 Release 编译和测试、受影响 UI 检查/截图、合入主树后重验发布，记录实际边界。

**重点回归：** 同 ID 不同账号不能混写；权限撤销后不继续；取消保留已成功项；成功后补读失败只反馈刷新问题；翻页/切筛选/离页不把旧选择带到新列表。

# 媒体库多选入口与 Emby 批量操作

> 执行使用 writing-plans、subagent-driven-development；按 CLAUDE.md 验证和交付。

**目标：** 多选入口移入媒体库封面更多菜单；勾选框在左上，选框只包封面；Emby 支持用户截图的批量操作。

**方案：** 保留 ItemsView 原生选择与辅助功能，PosterCard 只绘制封面选框。页面提供选择回调，其他页面不出现多选入口。Core 负责同源权限、协议与逐项结果；Shell 负责选择参数、确认、播放及状态更新。

**范围：** 播放子菜单、随机播放、添加合集、添加播放列表、收藏、已播放、转换、删除、移除识别、刷新元数据、扫描媒体库文件。Jellyfin/Plex 保留各自已有能力，飞牛不新增多选。

**约束：** 不改真实账号/媒体库，不用真实播放验证；协议先读上游源码；并行写入使用独立工作树。

- [x] 封面选框、左上勾选框、收藏角标隐藏恢复；页面契约及真实宽窄布局检查。
- [x] 多选入口移入封面更多菜单，点击选中当前卡；覆盖离页、换源、回收和无权限。
- [x] Core 批量协议和权限，覆盖拒绝、取消剩余、部分失败、成功后不重放写入。
- [x] 原生播放列表/转换参数与破坏性操作确认，接入选中项目播放队列。
- [x] 离线 UI 验证 Emby/Jellyfin/Plex、菜单范围与失败恢复；检查截图。
- [ ] 代码审查、当前 Release 编译与测试、提交；核对主树集成与交付状态。

## 审查重点

1. 同源并不等于权限不变：每次操作前与异步等待后重验。
2. 菜单关闭、换页或换账号后，旧回调不能作用于新选择。
3. 成功写入与后续刷新分开记录；刷新失败不能重复请求。
4. 转换、播放列表与文件扫描必须采用各自正式接口，不能以类似操作替代。
5. 未选、已选、清空、退出、回收及卡片式/缩略图布局都保持标题不被选框覆盖。

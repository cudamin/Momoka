### R01-001 · P1 · 发布清理可穿过目录联接删除输出目录之外的文件

- 位置：`tools/publish.ps1:162–168`。
- 触发：`OutputRoot/publish` 或 `msix-stage` 是指向另一目录的 junction，而其下 `win-x64` 是普通目录。现有 `Resolve-Path` 保留逻辑路径，`StartsWith(OutputRoot)` 通过，随后递归删除实际目标；严格载荷守卫在这一步之后才执行。
- 后果：重新发布可能删除用户指定输出范围之外的数据，而非仅清旧发布件。
- 证据：在 Windows PowerShell 5.1 中提取并原样执行162–170行的唯一 foreach。逻辑 `output/publish/win-x64` 指向匿名 `outside-output/win-x64`，后者哨兵被删除；两个位置都在本次新证据目录内，未执行完整发布脚本。随后移除了本次 junction。
- 最小修正：在任何创建/清理前拒绝目标及所有祖先重解析点，复用已有 `Assert-PlainPath` 或等价的最终路径校验；同时用分隔符限定目录边界。仅改字符串前缀不足。
- 建议回归：普通目标可清、publish/msix-stage/OutputRoot各级junction均拒绝、外部哨兵不变，进程占用守卫仍在清理前生效。

### R01-002 · P2 · 状态查询带文件路径仍进入签名

- 位置：`tools/sign-release.ps1:64`、`374–377`、`403–407`。
- 触发：`-Status -Path <文件或目录>`。注释承诺只看状态，但只有Path为空才return，随后调用signtool sign。其他写入模式也没有与Status互斥的参数定义。
- 后果：用户查询状态时可能改写目标签名/字节，破坏既有哈希或签名。
- 证据：保留完整生产控制流，只替换证书发现、状态展示、签名器和验签边界；匿名状态+路径运行返回0，mock签名器被调用且输入字节变化，完整签名尾经字符串一致性断言。
- 最小修正：Status在任何变更分支之前只读返回，或拒绝与变更参数组合；建议回归零签名/证书/注册表写入、目标hash不变。

### R01-003 · P2 · Inno 的 SkipPublish 跳过载荷验收

- 位置：`tools/installer.ps1:44–48,61`、`tools/installer/Momoka.iss:55`。
- 触发：目录只剩 Momoka.exe 或缺失必需DLL/许可时运行 `installer.ps1 -SkipPublish`，入口只检查EXE存在就调用ISCC。
- 后果：缺内核、Vulkan或托管程序集的不完整目录仍能进入打包并报告安装包成功；与publish的SkipPublish仍调用验收器不一致。
- 证据：完整原脚本拷入匿名树，发布目录只有非PE Momoka.exe；模拟编译器被调用且脚本返回0。证据证明验证边界被绕过，不宣称真实安装包能安装。
- 最小修正：复用生产verify-publish对现有目录验收，传正确自包含模式；建议缺每类依赖/混旧DLL时在ISCC调用前拒绝。

### R01-004 · P2 · 解除下载标记失败仍返回成功退出码

- 位置：`tools/unblock-momoka.ps1:159–179`。
- 触发：ADS标记可读，但删除被权限拒绝；脚本输出“失败：标记还在”，最终没有非零退出。
- 后果：调用方/自动化收到0，无法据退出状态识别操作失败。
- 证据：完整控制流保留，Get-Motw固定返回匿名标记，Unblock-File与ADS删除均拒绝；日志报失败，子进程仍退出0。没有读写真实ADS。
- 最小修正：汇总任何失败后退出非零，保留逐文件信息；建议验证全部成功、部分失败、全部失败三种结果。

### R01-005 · P2 · MSIX/AppX 被可执行文件版本信息谓词排除

- 位置：`tools/unblock-momoka.ps1:61–75,95`。
- 触发：文件名匹配Momoka且扩展名为受支持的.msix/.appx，但Test-MomokaProduct只有.zip走容器分支；其余读取PE ProductName/CompanyName。
- 后果：正常ZIP容器形态的安装包没有PE版本资源，永远不进入候选，宣称支持的包无法解除标记。
- 证据：新建含匿名AppxManifest的真实ZIP容器，以.msix命名，执行原样提取的唯一谓词，ProductName为空且返回false。不代表该简化容器经过安装或完整MSIX格式验收。
- 最小修正：对MSIX/AppX读取并核对包身份/发布者，或明确撤销其支持；不能简单按扩展名放开任意文件。建议匿名合法/错误身份、损坏容器、EXE/ZIP原路径回归。

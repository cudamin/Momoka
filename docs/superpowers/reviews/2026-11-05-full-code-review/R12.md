## 确认缺陷

### R12-001 · P2 · 外部 GPU 渲染仍提供不会生效的 HDR 算法

- 位置：`src/Momoka.Shell/ViewModels/SettingsViewModel.Video.cs:37–38,171–172`、`SettingsViewModel.Applicability.cs:22–30`；`src/Momoka.Core/Mpv/HdrOptions.cs:11–16,55`。
- 触发：外部 mpv 选择 `vo=gpu`，在 HDR 卡选择 Spline、BT.2446A、ST2094-40 或 ST2094-10。设置和起播仍提供/下发完整算法目录。
- 后果：固定 mpv 的 `video/out/gpu/video.c:2869–2883` 白名单不支持四项，发警告并将曲线退回 auto；界面选择与实际算法不一致。GPU-Next 的对应实现接受这四项。只读设置与生产 HdrOptions 采证得到 `tone-mapping=spline`，完整真实 VM 算法 Choices 仍含四项；未测真实外部 mpv 版本、HDR 屏或画面差异。
- 最小修正：按有效渲染器过滤已证无效曲线，并收起已证仅 GPU-Next 消费的亮度/对比恢复从属行，保留偏好与切回恢复入口。渲染器/后端切换联动 HDR 卡。`SettingSection.UpdateRows:80–115` 只 reseed 旧选择，不替换 Choices，不能只生成过滤目录然后 UpdateRows；使用现有 Fill 或定点更新算法行。
- 回归：内置两管线 GPU-Next、外部 gpu/next 往返、保存专属曲线后的隐藏/恢复、导入/默认/缓存重入。现有 SettingsApplicability 只按 HDR 模式查峰值；已有外部 gpu Shell probe 仅查基础卡。根因由第二位审查者与主代理复核。

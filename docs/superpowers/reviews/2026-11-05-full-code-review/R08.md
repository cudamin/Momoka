## 已确认缺陷

### R08-001 · P1 · 切换同主机另一端口后，旧服务的资源 Cookie 被发送给新服务

- 位置：`src/Momoka.Core/MoviePilot/MoviePilotClient.cs:37–71,90–105`；`MoviePilotService.Availability.cs:39–54`；`src/Momoka.Shell/Composition/ShellServices.cs:142,148–149`。
- 客户端为单例，所有登录/API/图片共用一个 CookieContainer。配置改变仅清除缓存会话，未隔离 Cookie；Cookie 按主机和路径匹配，不按端口隔离。曾连接 HTTP 服务 A，再把配置改到同主机的另一个服务端口 B，B 的第一趟登录就携带 A 的资源 Cookie。
- 官方后端 `app/adapters/web/security/access.py:207–287` 签发带用户身份、权限和 `purpose=resource` 的 Cookie；HTTP 下不设 Secure，默认路径为 `/`。`349–362` 使用它认证资源请求。这不是无认证意义的界面偏好。
- 实际匿名双回环：使用生产无参数 `MoviePilotClient`，真实 `MoviePilotService.TestConnectionAsync` 先连 A，再修改 URL、用户名、密码连 B。A 有 4 次请求，B 有 4 次请求，B 的登录和其余 3 次读取均收到 A 的占位资源 Cookie。两端始终保留监听，完成接收任务后才读计数；无重定向、真实账号或真实令牌。见 `repro-results.json` 的 `resource-cookie-cross-port`。
- 最小修正：按精确来源及账号/配置代次隔离传输和资源 Cookie 的所有权，图片读取使用同一捕获身份；旧响应只能回写旧容器。只清空共享 Cookie 不能防止旧在飞响应重新种入。无需修改其他媒体后端的 HTTP 架构。
- 回归：同主机不同端口、同源换账号、旧响应迟到、图片和 SSE 所属身份、拒绝跳转；断言新服务首次请求不带旧资源凭据。另一名审查者独立复核代码路径。

### R08-002 · P2 · 明确填写的 80/443 端口被改成 3001

- 位置：`src/Momoka.Core/MoviePilot/MoviePilotAddress.cs:85,119`；设置调用者 `src/Momoka.Shell/ViewModels/SettingMoviePilotRow.cs:158–161,205,230–236`。
- `Uri.IsDefaultPort` 同时为“未写端口”和“明确写了协议默认端口”返回 true。Normalize 把两种情况都替换成 3001，Split 又把明确端口显示为空。
- 实际 Core：`http://origin.invalid:80` → `http://origin.invalid:3001/`；`https://origin.invalid:443` → `https://origin.invalid:3001/`；IPv6 显式 80 同样丢失。明确 3000 保留，裸主机默认 3001 的对照正常。配置了 80/443 的反向代理/API 无法连接，重新打开设置也丢掉端口读数。
- 最小修正：在解析原始 authority 时区分是否显式指定端口，Normalize 与 Split 复用这一判断；保留裸主机默认 3001 的现有产品语义。补 IPv4/主机名/IPv6 的显式默认端口及保存重开回归。

### R08-003 · P2 · 服务端要求二次验证时错误提示“用户名或密码不正确”

- 位置：`src/Momoka.Core/MoviePilot/MoviePilotClient.cs:127–132`；设置反馈 `src/Momoka.Shell/ViewModels/SettingMoviePilotRow.cs:255–280`。
- 固定官方后端 `login.py:193–211` 在密码正确、账号启用 OTP 且未提交验证码时返回 401、`X-MFA-Required: true` 和 `data.mfa_methods=["otp"]`；`UserChain._verify_mfa:198–217` 证明该分支不是密码错误。官方前端 `pages/login.vue:697–764` 将它转为二次验证步骤。
- 本地所有登录 401 都提前改成同一句密码错误，丢掉挑战原因；本地表单和自动重登也没有 `otp_password`。匿名 handler 按该官方回话返回，实际客户端确实输出错误的密码提示且不返回会话。没有对真实 MFA 账号登录。
- 最小修正：区分明确 MFA 挑战、普通密码拒绝和其他 401，向用户准确说明需要二次验证及可用恢复方式，不引导反复改正确密码。若将 MFA 登录纳入支持范围，再接当前挑战的临时验证码输入与续期流程，不持久保存一次性验证码。完整 MFA 功能属于后续修复范围决定，本项不要求顺手增加通用认证框架。
- 回归：普通 401 文案保持、合法/未知 MFA 方法、挑战后取消、迟到挑战与重登；当前固定源码可确认差异，实际部署版本尚未核对。

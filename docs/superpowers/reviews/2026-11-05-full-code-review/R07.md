## 必要缺陷

### R07-001 / P2：同名条目下载会覆盖已有文件

- 位置：`src/Momoka.Core/Emby/DownloadPlan.cs:77–84`；`src/Momoka.Shell/Views/ItemCommands.Server.cs:368,380`；`src/Momoka.Core/Emby/EmbyHttp.cs:304`。
- 两部不同年份或不同来源的电影只要显示标题和扩展名相同，就落在同一目录、同一路径。文件名没有条目或来源身份，也没有现存文件消歧；传输完成后以 `overwrite:true` 替换原件，两个操作都报成功。清洗非法字符、截断到 96 字也会造成碰撞。
- 匿名反例执行实际 DownloadPlan、EmbyClient、EmbyHttp：两个不同 ID、年份 1990/2020 的条目得到同一路径，第一次内容 `FIRST-FILE` 被第二次 `SECOND-FILE` 替换。只写本树新证据目录的文本载荷，不读用户视频目录。主代理与命令审查者独立核对。
- 最小修正：在实际下载落点分配处保留已有文件、稳定消歧并保证原子落地，明确同条目重下载策略；补跨来源、同名不同年份、清洗/截断碰撞及并发落地回归。不能仅加年份，因为同年同名和不同版本仍会碰撞。

### R07-002 / P2：从详情货架删除本页主体或文件，遗漏主体失效处理

- 位置：`src/Momoka.Shell/Views/DetailPage.xaml.cs:2390–2396`；`src/Momoka.Shell/ViewModels/DetailViewModel.cs:3952–3955,3964–3981,4072–4135`；`src/Momoka.Shell/Views/ItemCommands.FnNas.cs:108–111`。
- 顶部“更多”使用捕获当前访问的 CaptureRemoval/CaptureReload；货架统一传裸 Remove/Reload。单集页的集带含当前集，对本集卡删除成功后，RemoveAsync 只摘货架、清播放目标，留下 `_detail/_seed/_actionsReady`。顶部已看、收藏和“更多”仍作用于已删除 ID。删除所属季时，同一路径还可能补选另一季播放目标而保留旧主体。

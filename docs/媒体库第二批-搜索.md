# 第二批：搜索人物、合集和播放列表

2026-11-11。在原有搜索分类后增加人物、合集、播放列表，原分类枚举数值保留。只有存在在线 Emby/Jellyfin 来源时显示新分类；选择新分类只读取这两家，Plex/飞牛继续使用既有媒体搜索。热门结果增加可打开的三类实体，结果仍按类型分组，空组不占空间。窄窗的分类栏可横向滚动。

人物打开原有作品网格（PersonIds），合集打开原有成员网格。播放列表读取各自成员协议并保留列表顺序；本批未增加列表管理操作。列表成员页收起不能改变这次读取的排序、筛选和字母跳转。近期搜索保留实体的类型、ID 与所属账号，重新打开仍走同一导航。

## 源码依据

实施读取了官方发布产物与官方服务端源代码，不把旧审查结论当作接口依据。

- Emby **4.10.1.0** 发布产物：本机 `work/媒体库网页端源码/emby-4.10.1.0/search/search.js`，原始字节偏移 4744 的 `getSearchResults` 使用递归 Items 搜索；5285 的分类型查询支持 Person/BoxSet/Playlist。`modules/emby-apiclient/apiclient.js` 的 `getItems`（73487）落到 `Users/{uid}/Items`；`getSearchResults`（100065）同时读取 ItemTypes。Momoka 本批采用明确已支持类型清单，未增加动态 ItemTypes 或其他媒体域。`item/item.js` 的 Playlist 读取使用 ParentId、ListItemOrder 和 SortOrder。本机快照版本来自此前官方发布镜像；本轮未重取目标服务器版本。
- Jellyfin Web **v10.10.7 / f4b8aa0ed4c5b571a3a6cc3bb027bb8ecebe5b68**：`src/hooks/searchHook/useSearchItems.ts:50` 通过独立 Persons API 搜人物，普通 Items 搜 Playlist/BoxSet。开发快照 **a953a95ed27f1761c979192ee432ea857ec3ba9c** 的 `src/apps/legacy/features/search/api/usePeopleSearch.ts` 保持独立人物请求；`utils/search.ts` 全局类型含 Playlist、BoxSet。该快照 `scripts/playlistViewer.js` 经 `Playlists/{id}/Items` 读取列表，传 UserId，不添加媒体排序。开发快照不是正式版宣告。
- Jellyfin Server **v10.10.7**：已读取 `Jellyfin.Api/Controllers/PersonsController.cs:GetPersons`、`Emby.Server.Implementations/Library/LibraryManager.cs:GetPeopleItems` 与 `Emby.Server.Implementations/Data/SqliteItemRepository.cs:GetPeopleNames`。旧 Persons 控制器只有 limit、没有 startIndex；仓库只在 `Limit > 0` 时加 SQL LIMIT，Limit=0 读取匹配人物全集，随后按当前用户可见性筛选。故本批只取带 SearchTerm 的人物匹配全集，按服务端顺序本地分页并用实际条数作为总数。每页重新读取匹配人物，宽泛人名会多一些响应；不会扫描全部电影或剧集。
- Jellyfin Server **v10.10.7** `Jellyfin.Api/Controllers/PlaylistsController.cs:GetPlaylistItems`（491–546）在用户访问权限通过后，取 `GetManageableItems` 原序，按 startIndex/limit 切页；成员 DTO 带 PlaylistItemId，总数是可见成员数。本批只消费原序成员，不加入写操作。

Jellyfin 普通媒体使用现有版本路由规则：10.x `Users/{uid}/Items`，12.x `Items?UserId=`；Persons 和 Playlists 成员是独立路由。令牌仍只在请求头。协议回归使用匿名 `.invalid` 内存 HTTP，没有访问真实服务、登录、写入或播放。

## 分页与取消

Jellyfin 热门媒体、人物分别拥有分页通道，人物条数不会改变媒体 startIndex。沿用 AggregateQueryCursor 的副本提交规则；新词、分类或离页取消旧查询，旧响应不会消费新游标或回填新结果。跨来源同 ID 按现有捕获账号身份区分。单来源任一路失败整页失败，聚合模式仍按现有来源失败反馈显示其余来源。

人物全集没有跨查询或登录的持久缓存。搜索结果仍使用稳定 Cards/SearchGroups 集合，分页只追加对应组。

# WinUI P4：布局、绑定与 DPI

日期：2026-11-13。起点 `29e9188`，本阶段保留仅深色、简洁模式窄窗封面、当前主窗口宿主及播放尺寸规则。

## 实现与调查

设置窗口原 `Fit` 先取页面下限，再与工作区上限比较。200% 缩放、工作区高于零但不足 960 物理像素时，480 DIP 的下限压过屏幕高度，居中后两边越界。新增 Core `ScreenPlacement.FitAxis` 统一这一尺寸换算：先按 DPI 换算，工作区始终限制最后结果，工作区足够时保留原 48 DIP 留白和页面下限。设置窗口 `Place` 使用这个真实函数，不变更主宿主、播放 FreeSizing 或窗口恢复规则。

已追 `DetailPage.OnBodySizeChanged → Viewport/PageWidth → RefitArtwork/SyncBackdrop` 与 `AnnounceShape`。宽高由页面实际视口负责；同类型完整主体不重复宣布版式，类型更正与重新 Attach 重新通知。没有证据要求机械更换这些现有所有者，保留代码并补实际 VM 请求在途跨断点回归。

音乐墙页尾作为独立单元见 [音乐分页](WinUI-P4音乐分页.md)。显式加载更多沿用曲目表语义，入口直接键盘可达，不新增自动网络加载。

## 支持尺寸与所有者

| 表面 | 当前范围/断点 | 尺寸与滚动归属 |
| --- | --- | --- |
| 主浏览 HWND/XAML 岛 | 客户区最小 600×560 DIP；常用 760/820/1100/1280 | HostWindow 负责原生下限与 WM_DPICHANGED 建议矩形，页面量实际视口 |
| 视频 FreeSizing/全屏 | 不沿用浏览下限 | 原播放管线与宿主负责，本批未改 |
| 设置 framework Window | 初始 1100×760 DIP，640×480 下限让给小工作区；860 DIP 紧凑状态 | 原生 Grid/AdaptiveTrigger；右侧 ScrollViewer、分类 ListView 各自滚动 |
| 详情 | 沉浸 820 DIP 断点；简洁电影/剧/季保持已确认窄窗封面行为 | Body ScrollView 为正文纵向滚动所有者，PageWidth 来自 Body |
| 音乐 | 曲目 ListView 与墙 ItemsView 分型，600/760/1280 验收目标 | 稳定 Rows 集合；独立墙页尾与播放栏避让 |
| 首页/媒体库横向货架 | 局部有限视口与独立横向滚动 | ShelfStrip；保持卡片宽度、锚点与选择，不改纵向页面所有权 |

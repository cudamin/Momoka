# 图片搜索来源与语言筛选

2026-11-13：图片选择弹窗新增「来源」和「所有语言」。两项都重新向服务器请求候选，不在已经取回的60张图片中本地过滤。选择来源后清空旧选择，过期响应和预览不得回填新一轮结果；请求失败保留恢复操作及本地上传。

## 当前产品范围

- 「来源」初始为「全部」，请求省略 `ProviderName`；单个来源原样转义后传 `ProviderName`。目录来自服务器当前图片类型的 `RemoteImageResult.Providers`，不硬编码 FanArt、TheTVDB 或 TheMovieDb；同时保留已返回候选的来源与当前选择作为缺字段时的恢复选项，不能据此断言来源目录完整。
- 「所有语言」沿用 Momoka 原入口的开启默认，显式传 `IncludeAllLanguages=true/false`。Emby/Jellyfin 网页初始关闭，这是本次保留既有产品默认的有意差异。
- 每次最多请求60张，沿用原有 `Limit=60`，本次不新增翻页。`TotalRecordCount` 仍保留服务器总数，不把60张上限当成来源完整性或总数。
- 服务器按条目的元数据语言筛选。「关闭」不能解释为仅中文或仅 Windows/应用语言；Jellyfin 10.10.7还保留无语言和英文图片，条目未指定偏好语言时不执行语言过滤。
- 图片选择是「编辑图片」里的现有子面板。上传、取消和图片类型的现有能力边界继续生效；没有候选并不意味本地上传不可用。

## 图三空态的原因边界

图三是搜索「Disc／光盘图片」后的无候选状态。原弹窗根据 `found.Providers.Count == 0` 断言「没有刮削源或未识别」，证据不足：同一条目有缩略图来源，不表示那些来源支持光盘图片；Providers反映适用图片类型的来源，不反映条目是否已经匹配。

Jellyfin服务器还可能把单家提供商异常转成空图片列表，HTTP200和Images空无法区分「上游没有图片」与「上游插件失败」。因此空态只描述没有找到当前类型的图片，不能凭空断言服务器插件配置、识别状态或网络正常。客户端收到的真实请求失败应独立报告，不能吞成无候选。

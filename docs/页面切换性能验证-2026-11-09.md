# 页面切换性能验证（2026-11-09）

用户要求首页、媒体库、详情页之间不要先停顿再切换，并以同服务器网页端为验收参照。

**验收结论：已显著优化，尚不能认定全部切换不慢于网页端。** 内部首次Rendering变快不等于屏幕已经完成显示；录屏仍有慢样本。不得把本次交付写成严格速度目标已经通过。

## 实现范围

- 浏览 Frame 直接交接内容，取消平台旧页先离场的等待；暖首页和历史返回不重新隐藏货架再淡入。
- Frame 的 Enabled 缓存容量为两页。成功的同配置首页复用货架、卡片、轮播及页面；普通根库同请求、同来源登录及查询/显示配置，且全库窗口起点和滚动偏移都为零时复用页面、卡片。数据在后台核对。
- 不符合条件时先清旧内容，再按现有 Attach/快照加载；换库零偏移明确归零，离页关闭库设置浮层。退出或切换账号释放全部 Enabled 缓存。
- 首页访问代次约束旧定时检查、实时通知及后台收尾。滚动锚点恢复在同步布局后重新检查访问与滚动控件归属，防止卸载中途空引用。

搜索、收藏、推荐、子目录、深处滚动及未成功完成的库不保留页面，继续原快照/锚点恢复。MP 订阅仍按原逻辑刷新；轮播图片离树仍释放。缓存有容量及卡片数限制，代价是短期保留最多两个浏览页面的控件和已加载内容。同一卡片暖海报和轮播暖返回不重播淡入；新卡、首次进入和自动轮播保留动效。

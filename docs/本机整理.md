# 本机整理

设置 → 本机整理。支持添加多个媒体库，一个源目录对应一个媒体库，分别设置名称、目标、识别来源和整理方式。首页的「媒体库」区域为每个本地库显示独立卡片，进入后只展示该库已经入库的内容。

识别方式可选 Momoka（直连 TMDB）或 MoviePilot。Momoka 需要 TMDB 帐号的 API Read Access Token，填入页面并保存，令牌由 Windows 加密保管；不依赖 MoviePilot。MoviePilot 使用现有连接，只提交源目录下的相对路径文本，不上传视频，也无需共享目录。实际部署的 MoviePilot 版本仍需对应接口支持。

整理方式独立选择：

| 方式 | 文件结果 |
| --- | --- |
| 直接改源文件名 | 在原目录改视频及同名字幕的名称；NFO、图片按视频名写入原目录 |
| 硬链接 | 在目标目录建立规范命名的链接；源和目标须同卷，共享视频内容 |
| 软链接 | 在目标目录建立指向源的链接；源移动或删除后链接失效，Windows 可能要求开发者模式或链接权限 |

添加媒体库并保存规则后，可手动扫描、校正、确认整理，也可开启「自动监控并刮削入库」。开启时会确认目录范围和整理方式，已有与新增文件都会自动处理。监控在 Momoka 运行期间有效，关闭设置页继续，退出应用停止。

自动处理先等待文件大小与修改时间稳定，并确认没有程序持有写入句柄，再读取识别信息。唯一可靠的匹配才自动整理，多候选、缺季集或错误列为待校正。视频和 NFO 成功后才登记入库，图片失败显示部分未完成。持续保存处理记录，重复事件、应用重启和部分失败不会自动重放写操作。首页与打开的库页面随入库更新。

识别不足时点「校正」，搜索正确作品，指定季集（特别篇为第0季），更新预览。手动勾选后确认视频、字幕、NFO和图片路径再执行。目标已有同名文件不覆盖；修改规则使旧预览失效，保存后才生效。移除媒体库仅停止监控、移除首页入口，文件和整理结果保留。

不处理音乐和多集范围，不触发远端媒体服务器刷新或播放。链接输出按「作品 (年份)/Season NN」组织剧集；直接改名保持原目录层级。文件系统拒绝检测到的重解析目录及非本机盘，硬链接不降级为复制。源目录不能重复或嵌套，也不能与另一媒体库的输出重叠。当前本地库页可查看已入库内容和打开所在文件夹，尚未接入应用内本地播放；首页仍沿用现有登录入口。

## 开发验证

先按开发文档编译当前 Release Tests/Core/Shell，然后执行主测试的 `local-media-fixture`，以及 `local-media-vm-fixture <本树当前 x64 Release Momoka.dll> <本树绝对根>`。前者包含临时文件的真实链接/改名、XML、图片、身份和匿名 HTTP；后者加载实际 VM，覆盖确认取消、校正失效和相对路径边界。

真实 WinUI 检查入口：`Momoka.exe --probe-shell --probe-section local-media --screen 1`。检查宽窄页面、确认取消、三种方式和两种来源、断线及恢复、多库后台处理已有及新增、首页实时卡片与逐库列表。只用独立运行目录和匿名 handler，禁止服务器整理请求。与其他桌面诊断和完整主测试串行。源码/匿名测试不等同用户服务版本或真实媒体操作验收。

`local-library-coordinator-fixture <本树Shell DLL> <本树根>` 验证实际协调器保存失败、取消和双库自动入库；`tests/Momoka.LocalLibraryPageTests` 源链接实际库页面 VM/Row，验证换库/离页、集合稳定和本机图片读取。应用的普通自检/截图诊断启动不会开启保存的真实目录监控。

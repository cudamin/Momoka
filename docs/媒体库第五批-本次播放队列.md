# 媒体库第五批：本次播放队列

2026-11-12，开发树 `library-batch5-queue/Momoka`，基线 `a072a8b`。当前视频更多菜单补「下一项播放」「追加到队尾」。仅在已建立的视频播放仍属当前起播意图、账号在线时显示；电影、单集、普通视频和预告可加入，音乐与剧/季等容器沿用其自己的播放路径。

`SessionPlaybackQueue` 只存在本次运行内存，不发服务器写请求、不保存到配置。每个待播槽冻结原账号作用域；相同 ID、甚至相同媒体重复排入仍是不同槽。用户安排的下一项插到待播头，追加跟在已有待播尾；已接受的「播放全部」保留原剩余顺序与各槽导航上下文。

集成播放时浏览页被播放层收起，卡片入口不可达，因此播放画面原生菜单另接「本次播放队列」→「下一项播放…／追加到队尾…」。两管线经同一VM事件请求原生只读搜索/多选框；安排冻结当前播放意图、尝试、原条目和账号owner，换片/退出后旧结果不能加入新队列。选中项按屏幕顺序追加，下一项多选倒序插入以保持该顺序；弹框期间暂停播放器键盘处理，关闭只取消选择。独占菜单同步消息契约，真实uosc/native操作仍未执行。

自然 EOF 优先取本次待播头，显式安排不依赖「自动播放下一集」开关。队列空时保持原自动下一集判断。`PlaybackTicket.PendingQueue` 让 Core 在 EOF 时读取本次待播状态，复用既有内核保留/释放合同；关闭窗口、停止、来源撤销和取消继续沿用原闸。集成和外部后端并不因此取得独占可复用句柄。

待播项只在真实 `NowPlaying` 确认建立后消费。准备或启动失败不重复提交已确认项，未确认项留在更多菜单的「本次播放队列」→「继续本次队列」，也可「清空待播项」。用户停止、手动点另一部、开始音乐或结束程序清空；换版本与原剧集导航不重建服务器清单。账号撤销的待播项直接丢弃，绝不改绑到当前账号或重登后的新 owner。

菜单沿用原生 `MenuFlyoutItem` / `MenuFlyoutSubItem`。核对 WinUI Gallery 固定 `6de91feccadfbb0a796b71caedead5a2284f730e` 的 `WinUIGallery/Samples/MenuFlyout/MenuFlyoutPage.xaml` 和 `.xaml.cs`：原生项、子菜单、图标、Click 和 Tag 对应样例行为；没有引入 Gallery 实验依赖。Momoka 仍使用当前 Shell 的稳定 WinUI `2.3.9`。本次是产品队列安排，没有复刻 mpv 的全局 playlist 状态或服务器持久列表。

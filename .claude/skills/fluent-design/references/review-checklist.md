# Fluent 2 验收清单

用途：把「看起来对不对」变成可逐项判定的检查。每项都要有实际观察到的证据；只读代码只能证明用了哪个令牌，不能证明渲染结果。

## 1. 验收前置

先写清楚这次验收的范围，避免用一整屏的结论覆盖全部界面：

| 项 | 取值 |
| --- | --- |
| 界面 | 页面 / 对话框 / 浮层 / 设置页 / 列表 / 空状态 |
| 标准 | Fluent 2；Windows 分支按 WinUI 3 |
| 主题 | 产品提供的全部主题 + 跟随系统；至少覆盖浅色与深色，记录实际深浅 |
| 宽度 | Fluent 2 六档（320 / 480 / 640 / 1024 / 1366 / 1920）或 Windows 分支 640 / 1008；写明用哪套 |
| DPI | 100% / 150%（至少两档） |
| 输入 | 鼠标 / 键盘 / 触控（如支持） |
| 特殊状态 | 高对比、关闭动画、远程桌面、透明效果关闭 |
| 数据 | 匿名夹具或已授权账号；记录数据规模 |

## 2. 标准判定

先回答五个问题，再进检查表：

- [ ] S1 设计表达是否用 Fluent 2 别名令牌（`colorNeutral*`、`colorBrand*`、`spacing*`、`borderRadius*`、`shadow*`、`duration*`）？
- [ ] S2 Windows 分支是否映射到 WinUI 主题资源，而不是在页面里写死 hex 或尺寸？
- [ ] S3 Fluent 2 值与 WinUI 值的差异是否记录（例如 `colorNeutralBackground1` `#ffffff` vs `SolidBackgroundFillColorBase` `#F3F3F3`）？
- [ ] S4 是否避免了 web-only 值（`caption2` 10px、`subtitle1` 20/26、`title3` 24px、`title1` 32px）？
- [ ] S5 交互态方向是否正确（web 越交互越深；Windows 越交互越亮）？

任何一项为「否」，先修正再继续。

## 3. 检查表

### A. 层级与表面

- [ ] A1 每个区域能明确归入 base / content / overlay，且只使用该层的材质与圆角。
- [ ] A2 页面根没有额外铺不透明底色，Mica 能透出（除非内容需要独立底色）。
- [ ] A3 卡片外没有多余的 Border 或「卡片套卡片」。
- [ ] A4 浮层有 1px 描边与阴影；卡片默认只有 1px 描边。
- [ ] A5 同一屏没有同时出现两套表面语言（例如 Mica 卡片 + 实心卡片）。

### B. 排版

- [ ] B1 Windows 界面只用 Windows 分支的 8 个样式（7 个字号）：12 / 14 / 18 / 20 / 28 / 40 / 68。
- [ ] B2 没有使用 web-only 的 `caption2` 10px、`subtitle2` 16px、`title3` 24px、`title1` 32px。
- [ ] B3 字重只有 Regular 与 Semibold；没有 Bold、Italic 强调。
- [ ] B4 页面标题 28、区块标题 20、正文 14；层级不超过三级。
- [ ] B5 正文行宽 50–60 字符；宽屏没有铺满整窗。
- [ ] B6 溢出用省略号；没有硬裁或文字压住相邻元素。
- [ ] B7 文案句首大写；专有名词与用户输入保持原样。

### C. 颜色

- [ ] C1 没有硬编码颜色（`#RRGGBB`、`White`、`Black`、命名颜色）。
- [ ] C2 设计表达用 Fluent 2 别名令牌；代码用 WinUI 主题资源，二者有映射记录。
- [ ] C3 文本使用 `colorNeutralForeground1/2/3/Disabled` 或对应 WinUI 四档，语义正确。
- [ ] C4 正文对比度不低于 4.5:1；大字与图形不低于 3:1。
- [ ] C5 品牌色只用于主操作、选中态、进度、链接；没有大面积铺色。
- [ ] C6 品牌底上的文字用 `colorNeutralForegroundOnBrand` / `TextOnAccentFillColorPrimaryBrush`。
- [ ] C7 语义色配了图标或文案；没有只靠红绿区分状态。
- [ ] C8 交互态方向正确：Windows 分支变亮，web 分支变深。

### D. 间距与几何

- [ ] D1 间距来自 Fluent 2 ramp：0 / 2 / 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 28 / 32 / 36 / 40 / 48 / 52 / 56。
- [ ] D2 没有 14 / 18 / 22 / 26 / 30 这类不在 ramp 的值。
- [ ] D3 2 / 6 / 10 只用于图标对齐与紧贴，不是随意微调。
- [ ] D4 圆角来自 Fluent 2 令牌；Windows 控件 4、浮层 8；相接元素不圆角。
- [ ] D5 没有把 12px 圆角用在普通卡片或按钮上。
- [ ] D6 标准控件高度 32；紧凑 24；大按钮 40；没有用 `Height` 写死。
- [ ] D7 可点击目标不小于 40 × 40（Windows 分支），相邻目标间距不小于 8。
- [ ] D8 图标与文字间距 8；图标尺寸在同一界面内统一。

### E. 材质与高程

- [ ] E1 窗口使用 Mica；旧系统或透明关闭时回退为实心且可读。
- [ ] E2 Acrylic 只出现在浮层或临时表面；没有全屏亚克力。
- [ ] E3 没有材质套材质（Mica 上叠 Acrylic、Acrylic 上叠 Card）。
- [ ] E4 Fluent 2 阴影档位与 Windows 分支的描边/高程选择一致；卡片默认不加阴影。
- [ ] E5 高对比模式下层级仍能靠描边与表面色分辨。

### F. 状态与动效

- [ ] F1 每个可交互元素都有 Rest / PointerOver / Pressed / Disabled 四态。
- [ ] F2 按下有下沉（高程 2 降到 1），不是只换颜色。
- [ ] F3 选中态与悬停态可区分；选中不只靠颜色。
- [ ] F4 键盘焦点可见，双色环没有被裁掉或压住内容。
- [ ] F5 动效使用 Fluent 2 duration / curve，或明确记录 Windows 分支的 83 / 167 / 250 / 333ms。
- [ ] F6 只动 `Opacity` 与 `RenderTransform`；没有动布局属性。
- [ ] F7 退出动效配了淡出；同一状态变化只有一个动画。
- [ ] F8 关闭系统动画后，所有操作仍可完成，没有等动画的遮罩。

### G. 无障碍

- [ ] G1 所有交互元素可 Tab 到达，顺序与视觉顺序一致。
- [ ] G2 图标按钮有 `AutomationProperties.Name` 与 ToolTip。
- [ ] G3 读屏能读出控件角色、名称、状态；列表项能读出选中态。
- [ ] G4 高对比主题下文字、图标、焦点都可见。
- [ ] G5 没有仅靠颜色传达的信息。
- [ ] G6 200% 缩放下内容不被裁切，滚动可达。
- [ ] G7 错误提示可被读屏播报，且给出恢复动作。

### H. 响应式

- [ ] H1 在所选断点实际拉伸检查：Fluent 2 六档，或 Windows 分支 640 / 641 / 1008。
- [ ] H2 按内容区宽度判断布局，不是按窗口宽度。
- [ ] H3 Small 下导航收起、次要命令隐藏、内容单列。
- [ ] H4 宽窄切换后选中项、滚动位置、焦点不丢。
- [ ] H5 没有出现横向滚动条（除非是明确的数据表）。

### I. 文案与本地化

- [ ] I1 中英文资源键齐全，没有硬编码界面文案。
- [ ] I2 占位符、复数、日期、数字格式正确。
- [ ] I3 按钮文案用具体动词（如「删除」「保存」），破坏性操作写清对象；不用含糊的「是 / 否」。
- [ ] I4 错误文案说明发生了什么、下一步做什么，不暴露凭据与内部路径。
- [ ] I5 空状态有说明与主操作，不是只有一句「暂无数据」。

## 4. 证据记录模板

| 编号 | 界面 | 状态 | 判据 | 方法 | 结果 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |
| S3 | 媒体详情页 | 浅色 | Fluent 2 与 WinUI 值差异已记录 | 截图 + 令牌表 | 通过 | `artifacts/.../detail-light.png` |
| B1 | 媒体详情页 | 深色 | 字号属于 Windows 分支阶梯 | 截图 + XAML 检查 | 通过 | `.../detail-dark.png` |
| F4 | 设置页 | 键盘 Tab | 焦点环可见 | 截图 + UIA | 通过 | `.../focus-settings.png` |
| H3 | 主页 | 640 宽 | 导航收起、单列 | 截图 | 通过 | `.../home-640.png` |
| E5 | 播放页 | 高对比 | 层级可辨 | 截图 | 未验证 | 缺高对比环境 |

判定规则：

- 「通过」必须有本次实际观察到的截图、UIA 输出或运行结果。
- 「未验证」不能计入通过；写清缺什么条件、补验入口。
- 「不适用」要写理由，例如纯文档改动没有界面。
- 旧截图、旧报告、别人的结论不能当本次证据。
- 只读代码可以证明「用了哪个令牌」，不能证明「渲染正确」；涉及视觉结果必须看画面。

## 5. 按改动类型抽样

| 改动 | 至少检查 |
| --- | --- |
| 新页面 | S + A + B + C + D + F + H |
| 单卡片样式 | B + C + D + F |
| 对话框 / 浮层 | A + E + F + G |
| 主题或材质 | S + A + C + E + G4 |
| 动效 | F + G6 |
| 设置页 | B + D + F + I |
| 列表 / 集合 | B + C + D + F3 + H5 |
| 纯文案 | I |

## 6. 测量方法

- **截图**：同一窗口尺寸、同一数据、同一主题下对比；深色与浅色各一张；150% DPI 再一张。
- **UIA**：用 Inspect.exe 或自动化树核对名称、角色、状态、焦点顺序；截图不能替代。
- **宽度**：按所选断点拖到临界值，各截一张；不要只改设计稿。
- **主题**：逐套切换产品提供的主题与跟随系统，记录实际深浅；不要只测默认深色。
- **动画**：在系统设置里关闭动画后重跑关键路径；确认没有功能依赖动画完成。
- **高对比**：切换到高对比主题，检查文字、图标、焦点、选中态。
- **DPI**：100% 与 150% 各看一次；检查 1px 描边是否消失、图标是否模糊。

## 7. 常见违规与修法

| 违规 | 判定 | 修法 |
| --- | --- | --- |
| 把 WinUI 默认值当成 Fluent 2 规范 | S1/S3 | 先查 Fluent 2 令牌，再记录 Windows 分支差异 |
| 硬编码 `#0078d4` | C1 | `colorBrandBackground` / `AccentFillColorDefaultBrush` |
| Windows 界面用 `caption2` 10px | B2 | `caption1` 12px |
| Windows 界面用 `title3` 24px | B2 | `title2` 28px 或 `subtitle1` 20px |
| 看到 6px 或 10px 间距就判错 | D3 | Fluent 2 ramp 允许 2 / 6 / 10 |
| 按钮圆角 8 | D4 | Fluent 2 `borderRadiusMedium` 4 |
| 普通卡片圆角 12 | D5 | 4 或 8 |
| 卡片加阴影又加边框 | E4 | Windows 分支只留 1px 描边 |
| 把 web 的 hover 变深套到 Windows | C8 | Windows 控件越交互越亮 |
| 动效固定 200ms | F5 | 按平台分支：Windows 250ms 常规、167ms 快速 |
| 640 宽出现横向滚动 | H3/H5 | 单列、减列、收导航 |
| 图标按钮无名称 | G2 | 补 `AutomationProperties.Name` 与 ToolTip |
| 成功/失败只用红绿 | C7/G5 | 加图标与文案 |
| 空状态只有「暂无数据」 | I5 | 加说明与主操作 |
| 关闭动画后按钮无响应 | F8 | 状态先落，再播动效 |

## 8. 判定结论写法

一段合格的结论至少包含：

1. 验收的界面与状态范围。
2. 用的是 Fluent 2 标准还是 Windows 分支的哪套断点/主题。
3. 实际通过的检查编号与证据位置。
4. 失败项、未验证项及原因。
5. 是否阻断交付，以及补验入口。

示例：

> 媒体详情页（Fluent 2 令牌，Windows 分支 640 / 1008，浅色 / 深色，100% DPI）：S1–S5、A1–A5、B1–B7、C1–C8、D1–D8、F1–F8 通过，截图在 `artifacts/fluent/detail-*`。E5 高对比未验证（本机未安装高对比主题），不阻断本次样式改动，登记待验。H5 在 640 宽出现横向滚动，已修为单列后复测通过。

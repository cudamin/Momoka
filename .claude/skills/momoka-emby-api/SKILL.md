# Momoka — Emby Server REST 协议层

规则归 [CLAUDE.md](../../../CLAUDE.md)：授权、凭据、闸门与交付以它为准。本技能只记协议层本身容易误判的地方，不另立安全或发布政策。

**本技能只覆盖 Emby 服务器。** 接 Jellyfin 时基址不自动追加 `/emby/`、凭据走 `Authorization: MediaBrowser` 头、12.x 用户作用域路由不再带 `userId` 路径段（旧版保留其文档化路由）—— 差异与逐条对照见 [momoka-jellyfin-api](../momoka-jellyfin-api/SKILL.md)，本技能描述的传输层决定（重定向、错误翻译、超时、下载、脱敏）两边共用。

`src/Momoka.Core/Emby/` 是与服务器对话的全部落点。**功能语义**在领域技能和 `docs/` 下的功能文档；这里只讲"请求怎么发出去、失败怎么读"。规格对照基准是同一台服务器的同一份快照 —— 本技能是那些文档背后的协议面。

## 开始之前：先拿规格，别猜

服务器自己在基址下暴露完整 OpenAPI：

```
GET {ApiBase}openapi          # 例如 http://host:8896/emby/openapi
```

- **不需要任何凭据**：实测不带 `api_key`、不带 `X-Emby-Token` 也返回 200。
- 实测（2026-10-08，本机那台）：3.5 MB、OpenAPI `3.0.1`、`info.version` = `4.10.0.40`、434 条路径 / 500 个操作 / 340 个 schema。**这是观测值不是常量** —— 服务器升级就变，用之前重取一次。
- 官方 UI 壳：`https://swagger.emby.media/?url=<urlencoded 规格地址>`，仅用于匿名查看规格。不要把令牌填入这个第三方站点或 URL；需要鉴权的核对，通过进程内请求头直接访问受信任的服务器，并遵守 CLAUDE.md 的操作授权范围。
- 落盘快照在 `work/emby-openapi.json`（`work/` 已被 gitignore），只作离线对照，不作事实来源。

### 第二本字典：官方 SDK 仓库

规格拿不到（离线、对方关了 `/openapi`、只给了截图）时，Emby 官方把同一份规格生成成了多语言客户端：[MediaBrowser/Emby.ApiClients](https://github.com/MediaBrowser/Emby.ApiClients)。C# 那份 2026-10-17 读到的是 **4.10.1.0**，比本地快照新一档。

**只能查，不能引。** 它是 `netstandard2.0` + RestSharp 的生成物，方法返回 `Task<RestResponse<T>>`、没有 CancellationToken，绕开了本技能的全部传输层决定；仓库也没有 LICENSE 文件，文件头写 `Autogenerated Code. No license applied.`，而本项目按 MIT 分发。用途、查法、它答不了什么见 [官方 SDK 字典](references/official-sdk.md)。

## 三件反直觉的事

### 1. 客户端不调用 `/Items/{Id}/PlaybackInfo`

规格里它存在（GET + POST），但全仓没有一处调用。播放地址是 `EmbyUrl.Stream` 直接拼出来的：

```
Videos/{itemId}/stream{ext}?Static=true&MediaSourceId=…
```

`Static=true` 是让服务器原样吐文件而不是转码。**将来要接转码决策、直连判断或媒体源切换时，`PlaybackInfo` 才是入口 —— 但现在没有**，别照着规格假设已经有了。

### 2. 规格有缺口，客户端在用规格里没有的接口

本地 `4.10.0.40` 规格未登记客户端使用的 `GET Notifications/Services`、`GET / POST / DELETE Notifications/Services/Configured`，也未登记通知配置选项使用的 `GET Users` 和 `GET Library/VirtualFolders`。后两条分别由 `GetNotificationUsersAsync`、`GetNotificationLibrariesAsync` 调用，返回列表，不能直接替换成返回分页结果的查询接口。

**规格缺项不证明接口不存在，源码调用也不证明当前服务器支持它。** 分别记录源码请求、规格覆盖和实测证据；没有实测时保留待核实状态。发现新的缺口就登记到 [接口清单](references/endpoints.md)。

### 3. 参数名不一样不代表接口不一样

客户端用 `{itemId}` / `{Connection.UserId}`，规格用 `{Id}` / `{UserId}`：

| 客户端 | 规格 |
| --- | --- |
| `Users/{Connection.UserId}/Items/{itemId}` | `/Users/{UserId}/Items/{Id}` |
| `Users/{Connection.UserId}/PlayedItems/{itemId}` | `/Users/{UserId}/PlayedItems/{Id}` |
| `Items/{itemId}/Images/{imageType}` | `/Items/{Id}/Images/{Type}` |
| `Users/{sourceId}/CopyData` | `/Users/{UserId}/CopyData` |

是**同一条路**。用规格校对时按结构对，别按字面量 grep —— 字面量对不上是常态。章节图使用规格已登记的 `/Items/{Id}/Images/{Type}/{Index}`，其中 `Type=Chapter`；不要把它写成带任意尾部的通配路由。

## 别自己发明的地方

- **基址只在一处归一。** `EmbyServerAddress.Normalize` 把任何输入统一成恒以 `/emby/` 结尾的 `ApiBase`（用户粘进来的 `/emby` 先被剥掉再拼回）。所以 `EmbyUrl.Combine` 里的相对路径**不带 `/emby`**。
- **凭据通过受管逐请求头传递，传递通道同样要核对。** `EmbyHttp.SendAsync` 为每次请求设置 `X-Emby-Authorization` 和 `X-Emby-Token`，`EmbyUrl.Stream` 不带 `api_key`。播放由 `PlaybackHttpTransport` 逐请求、逐重定向管理认证，native全局 `http-header-fields` 清空；内置与外部后端只加载随机loopback能力地址，外部仍先核对IPC服务端PID。离开初始来源后不恢复认证，未知嵌套资源不能取得服务器头。不要将令牌放入 URL、启动参数或日志；范围与不支持的认证HLS/清单见 [播放技能](../momoka-playback/SKILL.md)。`EmbyHttp.Redact` 去掉日志 URL 的 query，不能代替这些传递边界。
- **逐请求头，别动 `DefaultRequestHeaders`。** v1 在每次调用前改它，一并发取海报就自己跟自己抢（`EmbyHttp.cs:13-16`）。
- **路径段要过守卫。** `LibraryId`（`EmbyClient.Libraries.cs:120`）和 `UserSegment`（`EmbyClient.Users.cs:130`）拒绝 `.`、`..` 和含 `/ \ ? #` 的 id，再 `Uri.EscapeDataString`。新写把 id 拼进路径的方法时照抄这两个，别直接插值。

细节：[传输层与鉴权](references/http-and-auth.md)、[接口清单](references/endpoints.md)。

## Subtitle search filters

Jellyfin alone adds native local subtitle upload in the shared dialog; do not send that route to Emby. Its explicit management grant, five-field Base64 DTO, version target and 204/unknown receipts belong to [momoka-jellyfin-api](../momoka-jellyfin-api/SKILL.md). Existing Emby source-bound search/download/delete remains separately verified.

For the More menu's subtitle editor, pass an immutable `ServerSubtitleSearch` through `ServerSubtitles` to `EmbyClient.SearchSubtitlesAsync`. Keep `MediaSourceId` bound to the file captured when the dialog opened. Send `IsForced=true` only when “仅强制字幕” is on; omit the query when it is off, rather than excluding forced subtitles with `false`. The current Emby web editor has no hash-match toggle: do not restore it from the older screenshots in the manual-download article or send `IsPerfectMatch` from this editor. See [the subtitle endpoint notes](references/endpoints.md#字幕) for the dated protocol evidence and the Jellyfin difference.

Deletion requires that same captured `MediaSourceId`; never call the Emby subtitle DELETE with only the parent item and stream index. `subtitle-target-fixture` covers per-file routing and snapshot/path changes through actual Core operations. Jellyfin file-source IDs represent version item IDs and select the route instead of this query parameter.

## Native Emby metadata editor

`EmbyMetadataEditor` owns scope-bound full JSON reads and saves; `EmbyClient.Metadata.cs` owns the Emby-only `Items/{ItemId}/MetadataEditor` catalog endpoint. Reuse `ExternalIdInfo` rather than guessing provider IDs or cloning the SDK model. `EmbyMetadataEdit` preserves untouched JSON, date precision, unknown locks and original credit/studio identity across list edits. The whole-item lock is `LockData`, not the `IsLocked` query filter. Saving is administrator-gated and a true no-op sends no POST. Details and dated evidence are in [the endpoint notes](references/endpoints.md#emby-原生元数据编辑目录2026-10-28).

The focused `emby-metadata-fixture` uses anonymous in-memory HTTP and is a subset of the full Core suite. `--probe-shell --probe-section metadata` uses real native controls with offline samples and inert save delegates. Neither proves real server write success. Library dialog colors are locally scoped so MoviePilot/default dialog surfaces remain unchanged; command and screenshot boundaries are in the development document.

## 验证

花絮特典经独立 `EmbyClient.Extras.cs` / `DetailViewModel.Extras.cs` 接入。Emby 前提是官方 `supportsExtras` 的视频判断，不读数量；Jellyfin 路由和数量前提另按其技能。`extras-fixture` 和 `detail-action-readiness-fixture` 使用匿名 HTTP/假播放，后者执行本树真实 Shell VM；`InspectDetailExtras` 才是宽窄原生菜单层。固定上游与未实现的 AdditionalParts 评估见本节上文。

Version size comes from `MediaSource.Size`. For an omitted source size, `GetItemAsync` can use the item's own positive `Size` only after exact path/source-item identity checks (or an unambiguous single source); it never copies another alternate version's size or a folder/series aggregate. Missing sizes with explicit alternate `ItemId` values use the already established Emby `Items?Ids` batch with `Fields=Path`, reading `Size` from returned DTOs; newest-first sorting uses `DateCreated,Path` in the same batch. The official fixed SDK `ItemsServiceApi.cs` and measured 4.10.1 OpenAPI list `Path`/`DateCreated` as Fields options but not `Size`: a DTO property is not proof of a request enum member. Do not send `Fields=Size` or rely on a server ignoring unknown fields. Size supplementation has a three-second total deadline; supplementary failures retain detail/known sizes, while caller cancellation propagates. Default order with known sizes or no explicit item IDs sends no extra request. The official SDK `BaseItemDto.Size` is `long?` at `MediaBrowser/Emby.ApiClients` commit `f8499bd9d0e356b8a204a27b142765494dc6f450`, `4.10.2.0 Release` (read 2026-11-02); earlier 4.10.1 read-only version responses separately returned each file's byte count on its own item and in the hidden-item batch. Jellyfin's measured 12.2.0 schema exposes `MediaSourceInfo.Size`, not `BaseItemDto.Size`, so size batches are Emby-only. `media-source-size-fixture` verifies anonymous per-file mapping, ID/path conflicts, shared request counts, unsupported field rejection, cancellation and the total deadline. This does not prove that a currently configured server returns a size for every file.

- 新增或修改请求路径时，先 `GET {ApiBase}openapi` 校对；规格里没有的，确认是缺口并登记进本技能。规格取不到时改查[官方 SDK 字典](references/official-sdk.md)，并写明依据的是哪一版 SDK。
- 传输层行为（重定向、401 分类、`.part` 清理、日志脱敏）有单测覆盖，改 `EmbyHttp` / `EmbyHttpRedirect` / `EmbyUrl` 后跑测试项目，而不是只跑界面检查。 `HttpDownloadErrorTests` 直接执行真实长下载入口，假传输覆盖 401／403／503 的空／部分错误正文、流取得等待、短截止后的状态保留、取消、释放／后项前进，以及成功下载超出该截止；不运行真实下载或 UI 队列。定向命令见开发文档。
- 活服务器核对走只读；写操作按 CLAUDE.md 的授权档位来。
- 报告实测、未覆盖与失败项；不把历史失败当成通过，不用改基线消除未经解决的红项。

## Legacy product correction

Saved-token restore can correct an old Emby label to Jellyfin after anonymous family-only probing of the original address and identity validation. Use the confirmed same-origin base, never strip a real proxy `/emby/` suffix by inference. A normal Emby profile retains its existing public-information failure fallback without probing unrelated products. Token/user/server mismatches and password fallback are covered by offline tests; this is not real-server verification. Password fallback retains the anonymously confirmed, product-corrected expected connection and checks product, API base, user and confirmed server ID before any credential save or adoption. The shared identity predicate permits a missing ID for old profiles; this restore branch additionally rejects loss of the ID confirmed in the same attempt. `restore-identity-fixture` runs 86 anonymous cases on the actual session/gateway and isolated settings IO, including auth-result/public-info mismatch and cancellation/generation/address guards. API-base-only cases exercise the production identity predicate directly, not a changed remote endpoint.

## Realtime notifications and credentials

`EmbyRealtimeProtocol.Handshake` builds a URL without credentials and reuses each product's request headers. Emby appends `embywebsocket` to its confirmed API base (normally `/emby/embywebsocket`), preserving proxy prefixes; do not substitute an alias from another client without checking that server. `EmbyRealtimeConnection` is shared by Emby, Jellyfin and Plex; FnNas has a separate task monitor. Reconnect reads the original scope's current connection, uses 1/2/4/8/16/30-second backoff, and is cancelled on source exit or leaving Home.

Emby uses `X-Emby-Token` plus device identity. The per-attempt `HttpMessageInvoker` sets `AllowAutoRedirect=false`: same-origin and cross-origin redirects are both rejected. Preserve default proxy behavior, disabled cookies and unpooled handshake connections; never restore query-string tokens to make a handshake pass. WebSocket frame keepalive is separate from Jellyfin's application heartbeat.

Only `MessageType=LibraryChanged` wakes the Home media check. `Sessions`, `RefreshProgress` and `UserDataChanged` do not. Momoka compares the first 24 IDs/order before reloading shelves and carousel, queues notifications received during a read, and prevents late baselines from absorbing unseen changes. This is a page-scoped update signal, not an OS notification or proof of a completed import.

**The generic 30-second Home polling fallback was removed on 2026-11-10.** The measured Emby 4.10.1.0 HomeSections response gave no `RefreshInterval` for its four `latestmedia` sections; only live TV `onnow` supplied 300000 ms. Do not generalize that live-TV interval to latest media. The official Home chain also does not requery merely because the socket reconnects. Entry/manual reads remain; events missed while disconnected have no replay guarantee. Official Emby merges remote changes for 3 seconds; Momoka retains its existing queue and fingerprint check rather than claiming identical DOM behavior.

Evidence and fixed upstream source hashes are in [媒体库实时更新](../../../docs/媒体库实时更新.md). On 2026-11-10, Emby 4.10.1.0 accepted the current header-only handshake with HTTP 101 and stayed connected for 150 seconds. No real import was arranged and no LibraryChanged was observed, so this is connection evidence, not end-to-end delivery. `realtime-handshake-fixture` and `HomePushRefreshTests` separately cover anonymous socket/redirect/reconnect and Home busy-state behavior; TLS/proxy scenarios and real import delivery remain unverified.

## 交付

## Server video playlists

Video-library pickers use `GetEditableVideoPlaylistsAsync` and require a declared Video media type. Every existing-list write reads a fresh Playlist DTO and refuses Audio/unknown targets even when CanEditItems=true; generic music callers do not borrow this video's write path.

`EmbyClient.Playlists` reads the single account's complete server-persisted directory; this is not its current playback queue. Emby preserves the native `CanEditItems` and refreshes that exact Playlist DTO before every write. Missing/false remains read-only without an administrator inference. `EmbyItem.PlaylistItemId` identifies an occurrence, so duplicate media keep distinct remove/move identities. The official Web's current-user Items/ParentId/ListItemOrder member read feeds its PlaylistItemId-based helpers; removal uses POST Items/Delete with EntryIds, and Move uses the entry plus a zero-based target. Jellyfin has independent CanEdit/query/DELETE handling in its skill.

The playlist-specific HTTP path confirms 2xx headers before optional creation-ID parsing. Accepted writes survive body IO, cancellation and result-publication failure; sent writes lacking a receipt throw `PlaylistWriteUncertainException` and require independent readback, never automatic re-write. The caller supplies `beforeWrite` to recheck the captured owner, permission revision and page after native permission reads. Empty video creation specifies MediaType=Video. Fixed source hashes and the 79-case anonymous actual-client fixture are recorded in [the endpoint notes](references/endpoints.md). No real playlist write or playback was performed.

改到协议层时同步本技能与 [docs/开发与验证.md](../../../docs/开发与验证.md) 的相关命令。`references/endpoints.md` 声明了对照的服务器版本与快照日期，**换基准时一起更新**。

## Collection membership

Session-level requests retain the established same-account retry after a manual logout/login overlaps automatic reauthentication. Resolve the available source by the original account key and full connection identity, capture client and permission revision together, and bind the result to the owner that actually sent the retry. A new identity gets its own user-state revision; an owner revoked before the response is published must not receive the result or lend it to a later login. Source-scoped operations still own their original lifetime and collection writes retain their original owner guards.

`CollectionManagement` binds add/create/remove writes to the original source and checks current permissions inside every `ExecuteAsync` attempt, including authentication retries. Emby uses the administrator fallback and an explicit item's `CanEditItems` override from the current web predicate; do not apply Jellyfin's `EnableCollectionManagement` as an Emby account grant. Removing uses POST `Collections/{id}/Items/Delete?Ids=...`, never `DeleteItemAsync`.

An Emby `CanEditItems=true` grant carries its producing request's `PermissionReadRevision`. A changed account snapshot invalidates this older grant, so it cannot override a current denial during add/create/remove or reauthentication. Fresh item grants still allow their ordinary-account override. The fingerprint includes the grant's revision to prevent retaining an old card after a fresh read.

An internal collection confirmation can increment the source revision during the same capability probe. Migrate that probe's system cache revision only for the same owner and matching previous revision, preserving its confirmed administrator result/version. Publish source and system caches before notifying outside both locks. Explicit client replacement still expires the old cache; a reentrant replacement from the notification must not be overwritten afterwards.

The library page prepares `CollectionMembership` only for its current BoxSet members. It includes source ownership, collection/member IDs and the current query token; leaving or changing that query invalidates old menu commands. Collection relations are not stored on the media DTO. Unknown permissions retain the existing server-rejection fallback. Core tests plus the actual library VM and extracted command fixture are anonymous and do not establish real server writes or rendered controls.

`LibraryCollectionsAsync` is registered in the library probe section and as `InspectLibraryCollections`. It invokes the real card More button, checks granted/denied/restored menus, removes one anonymous relation and verifies a remaining member plus preserved media/user state. Its screenshots and `collections-receipt.json` establish rendered coverage only when this current-tree probe actually runs successfully.

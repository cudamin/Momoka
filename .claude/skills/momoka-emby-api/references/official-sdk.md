# 官方 SDK 仓库：离线接口字典

[MediaBrowser/Emby.ApiClients](https://github.com/MediaBrowser/Emby.ApiClients) 是 Emby 官方把服务器 OpenAPI 规格生成成客户端的仓库，8 种语言各一份（C#、Java、JavaScript、TypeScript、Python、Swift5、Go，另有 Net.RestSharp）。master 对应最新稳定版，beta 分支对应 beta 服务器。

**它是字典，不是零件。** 查字段名、枚举值、参数拼写、某个接口存不存在用它；引依赖、拷代码、抄它的 HTTP 实现都不用。

## 读到的是哪一版

- `Clients/Version.txt` = `4.10.1.0 Release`，最后一次提交 2026-09-29（2026-10-17 核对）。
- 比 [SKILL.md](../SKILL.md) 里本地 OpenAPI 快照（`4.10.0.40`，2026-10-08）新一档。**引用时写明 SDK 版本号**，别写"官方 SDK 就是这样"——版本会跟着服务器稳定版往前走。
- 生成物不保证每个常量都跟着更新：`Client/ApiClient.cs` 里写死的 `UserAgent` 还是 `Emby.ApiClient/4.8.0.47`。看到过时的地方先当生成器遗留，不当成规格事实。

## 为什么不能当依赖

| 想做的事 | 结论 |
| --- | --- |
| 引 NuGet 或整份拷进 `src/Momoka.Core` | 不行 |
| 查字段名、枚举值、参数拼写、接口是否存在 | 可以 |
| 抄它的传输层实现 | 不行 |

1. **依赖与 Core 的取舍冲突。** C# 那份是 `netstandard2.0`，带 `RestSharp 112.1.0` + `ServiceStack.Text.Core 6.11.0` + `System.Text.Json 8.0.5`；`Momoka.Core.csproj` 现在一个 NuGet 都没有。
2. **传输层被 RestSharp 占死。** 生成的方法是 `Task<RestResponse<T>>`，**没有 CancellationToken**，返回的也是 RestSharp 类型。`EmbyHttp` 那套 30 秒总超时、异常层次、重定向的凭据边界、DPAPI 多账号、逐请求头，用它等于另起一套并且绕开这些；每个调用点还要再包一层。
3. **只认 Emby。** Jellyfin 的基址与 `Authorization: MediaBrowser` 头、飞牛和 Plex 的独立协议，它一个字都没有；`EmbyHttp` 里三个客户端共用一个 handler 的安排也用不上。
4. **规模与可读性反着来。** C# 那份 420 个 `.cs`、约 5 MB：338 个 Model、70 个 `*ServiceApi`、12 个 `Client`。单文件最大的 `LiveTvServiceApi.cs` 356 KB、`LibraryServiceApi.cs` 352 KB。全量引入与"单个文件能否读懂"相悖。
5. **许可。** 仓库**没有 LICENSE 文件**，每个生成文件头写 `Autogenerated Code. No license applied.`。本项目按 MIT 分发，**不要拷贝它的代码**（含 Model 类）进仓库；只读字段名和枚举值。

## 什么时候值得查

- `GET {ApiBase}openapi` 拿不到：离线、对方关了规格、只有截图。
- 核对容易拼错的字面量：`TranscodeReason`、`MediaSourceType`、`SubtitlePlaybackMode` 这类我们手写字符串的枚举。
- 规划尚未实现的能力：[SKILL.md](../SKILL.md) 记着"客户端不调用 `/Items/{Id}/PlaybackInfo`"，而这份 SDK 有完整的 `PlaybackInfoRequest` / `PlaybackInfoResponse` / `MediaSourceInfo` / `TranscodingProfile` / `TranscodeReason` / `TranscodingInfo`。将来接转码决策、直连判断或媒体源切换时，这是现成的模型参考。
- 判断 [接口清单](endpoints.md) 里的"规格缺口"是生成遗漏还是接口真不存在：SDK 和服务器规格同源，两边一起缺说明是规格的问题，但仍不证明服务器不支持。

## 怎么查

C# 客户端的路径是 `Clients/Emby.ApiClient/Emby.ApiClient/{Api,Client,Model}/`。不 clone，直接读：

```bash
# 列出全部 Model 名
curl -s "https://api.github.com/repos/MediaBrowser/Emby.ApiClients/git/trees/master?recursive=1" \
  | py -c "import json,sys;[print(x['path'].split('/')[-1][:-3]) for x in json.load(sys.stdin)['tree'] if x['path'].startswith('Clients/Emby.ApiClient/Emby.ApiClient/Model/')]"

# 读单个文件
curl -sL "https://raw.githubusercontent.com/MediaBrowser/Emby.ApiClients/master/Clients/Emby.ApiClient/Emby.ApiClient/Model/PlaybackInfoRequest.cs"
```

`raw.githubusercontent.com` 偶尔回空正文，重试一次或改用 `contents` API。仓库是公开的，不需要凭据；**不要把令牌放进这些请求**，也不需要访问第三方 swagger 站点。

## 读模型时的两条规矩

- **枚举值看 `[EnumMember(Value = "...")]`**，别看成员名，也别看赋的整数（`Default = 1` 只是 C# 枚举的序号）。
- **属性名就是 JSON 名。** 生成器保留了 PascalCase，但**没有 `[DataMember]` 标注**，所以不能从属性名反推 snake_case 或别的命名策略；拿不准时以服务器实际返回为准。

## 它答不了什么

- 服务器实际行为：支持、拒绝、返回形状都以 `GET {ApiBase}openapi` 和只读实测为准，SDK 只是"规格这么写"。
- 我们的规格缺口是否真的存在：同源，可能一起缺。
- Jellyfin、飞牛影视、Plex：没有。
- 鉴权、重定向、超时、脱敏：它的 authenticator 与 Momoka 的凭据边界不是一回事，别拿它当传输层依据。
- 版本漂移：master 跟稳定版、beta 跟 beta 服务器。写进文档时带上版本号与核对日期。
